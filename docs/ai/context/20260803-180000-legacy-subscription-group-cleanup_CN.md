# 遗留模型订阅分组清理

## 背景

`/purchase` 已调整为余额套餐：用户支付人民币后，在 28 天内每 7 天获得一次美元 API 余额，共 4 次。该语义不再关联模型分组或模型订阅。

此前一次初始化误创建了 7 个 `paid-subscription-*` 分组（ID 10-16）和 7 条 `subscription_plans`。它们分别重复了标准模型渠道分组 ID 3-9。

## 审计结果

- 每个遗留分组与对应标准分组的账号 ID、优先级完全一致。
- 所有分组均归属同一现有渠道，标准分组的渠道绑定已存在。
- 遗留分组没有 API Key、支付订单、用户订阅、用户授权、使用记录、审计日志、监控指标或调度任务依赖。

## 处理决策

新增迁移 `195_cleanup_legacy_paid_subscription_groups.sql`：

1. 仅识别 ID 10-16 且名称为 `paid-subscription-*` 的完整已知集合。
2. 执行前复核名称、平台、账号绑定和优先级是否仍与 ID 3-9 一致。
3. 检查 API Key、支付订单、用户订阅、用户授权、使用记录等业务依赖；任一存在则中止事务。
4. 先删除 7 条错误的订阅计划，再删除重复分组。账号和渠道绑定由外键级联清理，标准分组及其绑定保留。

迁移为前向、幂等数据修复：新环境没有这些遗留记录时不做任何操作；已存在且未被使用时可安全清理。
