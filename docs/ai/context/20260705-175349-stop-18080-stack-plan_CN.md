# 停止 18080 本地 Sub2API 栈操作计划

## 目标

确认 `127.0.0.1:18080` 是否仍运行 Sub2API；若仍运行，只停止 18080 对应的应用容器、PostgreSQL 容器和 Redis 容器，不影响 `127.0.0.1:18084` 公网候选部署。

## 当前只读核对

- `sub2api` 正在运行并占用 `127.0.0.1:18080->8080/tcp`。
- `sub2api-candidate` 正在运行并占用 `127.0.0.1:18084->8080/tcp`，属于需要保持运行的公网候选栈。
- `sub2api`、`sub2api-postgres`、`sub2api-redis` 使用同一个 `deploy_sub2api-network`，服务别名分别对应应用、`postgres`、`redis`，可判定为 18080 栈。
- `sub2api-candidate`、`sub2api-candidate-postgres`、`sub2api-candidate-redis` 不在本次停止范围。

## 操作边界

- 只执行 `docker stop sub2api sub2api-postgres sub2api-redis`。
- 不删除容器、镜像、volume、network。
- 不执行 compose down，避免按 project 维度误伤其他容器。
- 不停止、不重建、不重启 `sub2api-candidate*`。
- 不修改 nginx、Cloudflare Tunnel 或公网路由。

## 验证

- 停止后确认 `docker ps --filter publish=18080` 无运行容器。
- 确认 `sub2api`、`sub2api-postgres`、`sub2api-redis` 为 `Exited`。
- 确认 `sub2api-candidate`、`sub2api-candidate-postgres`、`sub2api-candidate-redis` 仍为 `Up`。
- 请求 `http://127.0.0.1:18084/health`、`http://127.0.0.1:8080/health`、`https://api.aaccx.pw/health`，确认公网候选链路仍可用。
