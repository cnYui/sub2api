# 2466439791@qq.com request timed out 排查计划

## 目标

排查用户 `2466439791@qq.com` 当前反馈请求一直 `request timed out` 的原因，并确认该用户实际发起请求数量、成功落库数量、失败日志是否进入 Sub2API。

## 约束

- 不修改用户、Key、订阅、分组、上游账号、nginx 或运行配置。
- 不记录完整 API Key，只记录掩码和内部 id。
- 优先用只读 SQL、容器日志和公网最小复现定位问题。

## 排查路径

1. 查询 `usage_logs` 中该用户和 Key 的成功落库请求数。
2. 查询 `ops_error_logs` 和 `ops_system_logs` 中该用户、Key、相关 request id、超时关键词和近期错误。
3. 查看 Sub2API 容器近期日志，定位用户请求是否到达、是否上游超时、是否入口断开。
4. 必要时用该用户 Key 发一个带较短超时的公网最小请求复现，并对比系统日志。
5. 新建结果文档记录结论，不记录完整 Key。
