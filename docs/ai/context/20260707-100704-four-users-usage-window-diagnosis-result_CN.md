## 代码层根因

本地当前实现位于 `backend/internal/repository/user_subscription_repo.go`：

```sql
daily_usage_usd = CASE
  WHEN daily_window_start IS NOT NULL AND daily_window_start < $2 THEN 0
  ELSE daily_usage_usd
END,
daily_window_start = CASE
  WHEN daily_window_start IS NULL OR daily_window_start < $2 THEN $2
  ELSE daily_window_start
END
```

这段逻辑会把 `NULL` 窗口补成今天，但不会清掉 `NULL` 窗口上的旧用量。对已有历史用量但窗口为空的订阅，这是错误语义。

## 建议后续修复

- 代码修复：`daily_window_start IS NULL` 时也应该清零 `daily_usage_usd`，weekly/monthly 同理需要按业务语义确认是否清零。
- 运行态修复：对当前 active 订阅按 usage_logs 重新校准窗口与今日用量，规则沿用 2026-07-06 的“没有今天成功用量则清零，有今天成功用量则写回今天聚合值”。
- 管理端优化：订阅列表展示前不应直接信任陈旧 `daily_usage_usd`，至少需要在后台任务或查询层统一刷新窗口。
