# DeepSeek 单条价格复核

## 对照记录

在 `api.ai-genesis.app/usage` 的 API Key `deepseek` 明细中，截图对应记录为：

- 模型：`deepseek-v4-flash`
- 输入 token：`54`
- 输出 token：`22`
- 输入单价：`$0.14 / 1M Token`
- 输出单价：`$0.28 / 1M Token`
- 中转倍率：`3.5x`
- 页面用户扣费：`$0.000048`

本地 `billing_service.go` 对 `deepseek-v4-flash` 使用相同标准单价，18082 实例数据库中的 DeepSeek 分组倍率为 `3.5000`，容器环境中的最终倍率为 `15`。

## 复算

```text
输入费用 = 54 × 0.14 / 1,000,000 = 0.00000756
输出费用 = 22 × 0.28 / 1,000,000 = 0.00000616
标准成本 = 0.00000756 + 0.00000616 = 0.00001372
中转站实际费用 = 0.00001372 × 3.5 = 0.00004802
```

页面显示金额保留六位小数，因此为 `$0.000048`，与复算一致。若该笔请求经过本地余额扣费链路，最终扣费为：

```text
0.00004802 × 15 = 0.00072030
```

结论：DeepSeek 这条记录在本地最终 `15x` 之前的费用与别人中转站的用户扣费一致；本地余额扣费是在该一致的中转站费用基础上再乘 `15x`，不存在额外重复乘 `3.5x` 的问题。
