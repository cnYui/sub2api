# Kimi K3 上游最终费用口径确认

## 截图证据

用户提供的 `api.ai-genesis.app/usage` 记录为：

- API 密钥：`k3`
- 模型：`kimi-k3`
- 输入 token：`138`
- 输出 token：`52`
- 页面费用：`$0.004179`

按本地 Kimi K3 标准单价计算：

`138 × 3e-6 + 52 × 15e-6 = 0.001194`

截图费用满足：

`0.001194 × 3.5 = 0.004179`

因此截图中的“费用”已经是上游中转站完成 `3.5x` 后的最终费用，不应再对这个已完成的金额额外乘 `3.5`。

## 与本地记录的关系

本地 `usage_logs.total_cost` 表示标准成本，不是上游网站的最终费用；本地当前实现用分组 `3.5x` 从标准成本重建上游实际费用，再应用本地 `15x`：

`total_cost × 3.5 × 15`

对于本次长上下文请求：

`0.0536268 × 3.5 × 15 = 2.815407`

这在数学上等价于：

`上游最终费用 0.1876938 × 15 = 2.815407`

但从业务语义上，正确基准应明确写成“上游最终费用 × 15”，不能把 `total_cost` 误认为上游最终费用后再叠加 `3.5`。

## 实现边界

当前上游 API 返回给本地请求的是 token 用量，不包含截图中这种逐请求最终费用字段；本地因此只能用标准单价和 `3.5x` 重建。若要严格以中转站账单为唯一事实来源，需要上游透传逐请求费用或提供可关联的账单接口。

本次未修改线上计费配置或余额数据。
