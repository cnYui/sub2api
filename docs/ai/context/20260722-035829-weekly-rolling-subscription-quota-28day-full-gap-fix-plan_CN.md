# 2026-07-22 周滚动订阅额度与 28 天周期收口实施计划

## 背景

用户要求按 `20260721-222923-weekly-rolling-subscription-quota-28day-design_CN.md` 逐项补齐实现，尤其关注前端页面没有完全切换、后端周窗口错误元数据、退款撤销目标权益段后未来续费权益被误失效，以及本地迁移 dry-run 仍存在阻塞对象。

本轮只在本地工作树实施和验证，不操作公网、生产数据库、Nginx、Cloudflare 或 CLIProxyAPI。

## 本轮必须补齐

1. 后端周额度耗尽必须带精确 `window_resets_at`，确保 Gateway 可映射 429 与 `Retry-After`。
2. 普通退款只撤销目标 entitlement period；若还有未来权益段，订阅保持可恢复状态，空档期由“当前无生效权益段”判定不可用。
3. 管理端订阅页不得用前端 `weekly_window_start + 7 天` 自行推导公共滚动周刷新时间。
4. 用户购买页、订阅页、Dashboard、Key 用量、退款弹窗和管理端相关页面继续复核旧“日额度 / 24 点 / 30 天”文案，只改公共 Codex 周额度路径。
5. 增加或强化后端、前端测试，覆盖上述回归点。
6. 新建结果上下文，记录 dry-run 阻塞、验证命令、未执行 cutover apply、未部署状态。

## 取舍

- 不自动执行 cutover `--apply`：当前 dry-run 仍有历史重叠权益、缺失权益和无法归属 usage facts，设计要求异常对象禁止自动迁移。
- 不重写平台账户配额、非公共订阅日/周/月逻辑：这些不属于公共 Codex 周滚动切换范围。
- 前端用户可见额度继续使用统一整数 USD formatter；精确限额只由后端字段和后端判断承担。
