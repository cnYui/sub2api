# 流量卡正额度准入规则更正

## 管理员确认的最终规则

1. 普通余额大于等于 `0` 时不切换流量卡；包括余额低于 `0.01 USD` 的正余额，只按普通余额保底阈值拒绝，不消耗流量卡。
2. 普通余额小于 `0` 后，下一次请求不得继续扣普通余额，必须从用户级全渠道流量卡额度池结算。
3. 流量卡净剩余额度必须严格大于 `0` 才允许发起下一次调用；额度为 `0` 或流量卡欠费抵扣后无净额度时拒绝。
4. 负余额 + 正流量卡额度的调用可以使流量卡在本次结算后归零或形成流量卡欠费；下一次请求会因流量卡净额度不大于 `0` 被拒绝。

## 实现调整

- `BillingCacheService.CanUseTrafficPackCredit` 从“至少达到 `MinimumBalanceReserve`”改为“净剩余额度 `>0`”。流量卡只有极小正余额时仍允许完成一次调用，符合额度池的实际结算规则。
- 余额扣费事务已按既有实现保证：普通余额小于请求费用时不再扣减普通余额；若锁定后的普通余额已为负，优先扣流量卡，未覆盖部分写入 `traffic_credit_debt_ledger`。
- 下一次请求的准入以流量卡摘要净额为准；仓库在 `TotalRemainingUSD` 中扣除了流量卡欠费账本，归零或负数均拒绝。
- 主 API、Gemini 原生 API、Antigravity Gemini 入口统一使用同一负余额切卡规则，对所有用户生效。

## 回归验证

新增/更新测试覆盖：

- 负余额 + 任意正流量卡额度放行；
- 负余额 + 无流量卡拒绝；
- 零余额或正余额低于 `0.01 USD` 不切换流量卡；
- 流量卡额度为 `0` 拒绝；
- 主 API 与 Gemini 认证入口行为一致。

相关定向 Go 测试已通过。该更正仍需随应用镜像发布到生产 `sub2api-official-18082` 后，才会影响公网请求。
