# 周滚动订阅额度与 28 天周期缺口补齐计划

## 范围

- 继续实现 `20260721-222923-weekly-rolling-subscription-quota-28day-design_CN.md`。
- 只修改本地代码、测试与上下文文档。
- 不执行 cutover `--apply`，不操作公网、生产数据库、Nginx、Cloudflare 或 CLIProxyAPI。

## 已发现缺口

1. 管理员普通订阅退款虽然前端禁用手填金额，但后端网关退款提交前没有像用户退款一样在事务内锁定订单、目标权益段和 usage facts 后二次计算 quote。
2. 管理员退款兜底分支仍保留整条 `RevokeSubscription` 路径；退款语义应只撤销目标订单权益段，避免影响后续续费权益。
3. 顶部迷你订阅进度已使用有效周额度和整数 formatter，但缺少周窗口精确重置时间展示。

## 实施策略

- 复用现有用户退款事务形态，为管理员普通订阅退款增加事务内 quote 重算与 `refund_basis` 持久化。
- 支付网关调用前只提交“退款中 + 不可变退款依据”，支付成功后仍复用目标权益段撤销逻辑。
- 强制人工退款保持可手填金额，但必须带 reason，并继续写入 `force_refund` 与审计。
- 顶部迷你进度展示后端返回的 `weekly_window_resets_at`，不由前端推导自然周。

## 验证

- 补充后端单元测试覆盖管理员普通退款的事务内二次计算。
- 补充前端组件测试覆盖顶部迷你进度周重置时间。
- 运行相关 targeted tests，再根据影响面运行必要全量验证。
