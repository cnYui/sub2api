# 默认品牌图标替换设计

## 背景与目标

运行中的 `18080` 公共设置返回空 `site_logo`，因此首页、认证页、侧边栏、密钥用量页、法律页和浏览器 favicon 都回退使用前端静态资源 `frontend/public/logo.png`。

目标是在本地分支 `codex/replace-default-brand-logo` 中，将该默认资源替换为用户指定的 `red-only-transparent-sharpened.png`，并在不裁剪图案的前提下压缩为适合全站小尺寸展示的透明 PNG。后台未来设置 `site_logo` 时，仍保持原有优先级并覆盖默认资源。

## 方案

源图片为 `1149x928` 透明 RGBA PNG，原始大小为 `764,834` 字节。输出将采用以下固定规格：

- 等比缩放到最长边 `256` 像素，不裁剪内容。
- 在透明画布上居中补足为 `256x256`，匹配现有各处方形 Logo 容器和 favicon。
- 保留 RGBA 透明通道，使用 PNG 无损压缩，大小不超过 `100 KiB`。
- 继续使用既有资源路径 `/logo.png`，不改变页面组件、路由、接口或数据库设置。

该方案只替换默认回退资源；任何非空 `site_logo` 配置会照常优先展示，避免把一次默认品牌更新变成后台配置行为变更。

## 改动边界

功能性改动仅涉及以下文件；另外会按项目约定新增本设计文档和结果文档：

- `frontend/public/logo.png`：替换为压缩后的透明默认图标。
- `frontend/src/__tests__/brandLogoAsset.spec.ts`：在现有 PNG、尺寸和体积断言外，增加 RGBA 透明通道断言。
- 本文档及后续结果文档：保留设计、转换参数、校验结果和未部署边界。

不修改运行中的容器、Docker Compose、Nginx、数据库、Redis、后端设置，也不运行任何部署或重启命令。当前 `18080` 不会因本分支而发生变化。

## 测试与验收

先为 RGBA 透明通道补充测试并运行，预期旧 `logo.png` 因没有 alpha 通道而失败。随后生成资源，使测试重新通过。

验收包括：

- 资源测试确认 PNG 签名、`256x256` 尺寸、RGBA 颜色类型和不超过 `100 KiB`。
- 前端类型检查与生产构建成功。
- 静态检查确认站内默认 Logo 与 favicon 仍统一引用 `/logo.png`。

完整前端基线套件在单次命令时限内未返回汇总；本次相关资源测试在隔离工作区通过。实施完成后仍会再次运行完整套件，并明确报告其结果或时限限制。

## 风险与回滚

风险仅限默认图标在极小 favicon 尺寸下文字可读性下降；页面中现有 `object-contain` 会完整保留图案。若视觉检查不通过，只需丢弃该本地分支或在分支中恢复原 `frontend/public/logo.png`，不涉及运行态回滚。
