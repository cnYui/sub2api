# 负余额硬阻断与资金链防护实施计划

## 目标

本次变更解决的不是“页面显示负数”，而是计费资格与资金事实不同步：任何普通余额小于零的用户都不能继续执行模型调用，套餐后续周额度不能自动覆盖首周仍未还清的欠费，已完成的上游请求必须在释放本地请求资源前完成资金结算。

## 不变式

1. 模型调用进入上游前必须从 PostgreSQL 读取最新普通余额；余额小于零时，订阅和流量卡都不能绕过。
2. 余额等于零时仍可使用满足保底金额的 OpenAI 流量卡。
3. 上游成功产生费用后，统一计费事务必须同步完成；资金仓库缺失时标准模式拒绝降级透支。
4. 余额套餐首周额度先还债，仍欠费时状态固定为 `debt_paused`，后续额度等待管理员恢复。
5. 批量生图冻结普通余额时同步扣减套餐子账本，并持久保存冻结资金来源；捕获或释放时只恢复对应来源。
6. 余额发生变化后失效余额缓存；计费准入不以 Redis 余额作为最终事实。

## 实施顺序

1. 先补失败测试：负余额加流量卡、负余额加订阅、数据库新鲜余额覆盖旧缓存、WebSocket 每轮复核。
2. 实现数据库余额终检，并补主 API Key 与 Gemini API Key 的负余额早拒绝。
3. 将 handler 用量任务改为同步执行，保留计费后的日志和通知异步；标准模式缺失统一计费仓库时 fail-closed。
4. 实现 `debt_paused` 创建、运行中暂停、到期、展示、购买冲突和管理员恢复。
5. 新增数据迁移，将上线时仍有后续期数的负余额活动套餐幂等暂停并写支付审计。
6. 修正批量生图冻结与余额套餐 `remaining_usd` 的来源一致性。
7. 补前端欠费暂停展示，运行专项测试、类型检查、构建和后端回归。
8. 提交功能分支，合并到本地 `main` 后再次验证。
9. 以本地 `main` 重建应用镜像，只替换 `sub2api-official-18082`；不重建 PostgreSQL、Redis、数据卷或 Cloudflare Tunnel。
10. 核验迁移、欠费用户拒绝、零余额流量卡、18 倍最终倍率、本地健康检查、Nginx 配置和三个公网域名。

## 取舍

- 本次不实现请求前费用预授权。模型最终 token 数在上游完成前未知，因此多个已经通过终检的并发请求仍可能共同形成首次负余额；同步结算和每次 DB 终检把风险限制在已放行的在途请求，不允许后续请求继续扩大欠费。
- 标准模式不再使用非原子的旧计费仓库降级路径。宁可返回计费服务不可用，也不能在资金基础设施缺失时继续提供付费调用。
- 管理员恢复只重新开启下一周节奏，不延长套餐有效期，也不补发暂停期间错过的周额度。
