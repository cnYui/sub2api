# 上游账号凭证安全改造设计

## 目标

消除 Redis 调度缓存中的上游 API Key、OAuth Token、Cookie 等敏感凭证，并将 PostgreSQL `accounts.credentials` 中的敏感字段改为加密存储，同时保持现有调度、网关和管理端行为不变。

## 已确认现状

- `accounts.credentials` 是 JSONB，当前由账号仓储直接读写。
- 调度快照同时写入完整账号和元数据账号，完整快照包含 `credentials`，元数据快照也保留 `api_key`。
- 网关从调度快照按账号 ID 取账号，凭证目前依赖 Redis 快照提供。
- 项目已有 AES-256-GCM SecretEncryptor，但现有 TOTP 密钥的生命周期不适合直接复用到渠道凭证。
- 当前主工作区有管理员维护的未提交变更，本次实现必须在独立分支中完成。

## 方案

### Redis 调度缓存

1. 调度快照只保存账号 ID、调度状态、分组关系、模型映射和限流/配额等非凭证元数据。
2. `scheduler:acc:*` 与 `scheduler:meta:*` 均不得包含 `api_key`、`access_token`、`refresh_token`、Cookie、私钥等敏感字段。
3. 选中账号后，调度快照服务按账号 ID 从账号仓储读取完整账号；账号仓储负责解密凭证。缓存未命中时继续使用现有数据库回退路径。
4. 删除或重建快照时清理旧的完整账号键，生产 Redis 需要执行一次带前缀的清理，避免历史快照残留。

### PostgreSQL 凭证加密

1. 保持现有 JSONB 列，避免对账号表做破坏性结构变更。
2. 对敏感字段逐项使用 AES-256-GCM 加密，密文使用明确版本前缀，例如 `enc:v1:<base64>`；非敏感字段继续保持原有 JSON 类型，便于现有业务读取和过滤。
3. 读取账号时解密敏感字段；写入账号、批量更新、OAuth 刷新和导入路径统一先加密，避免任何旁路写入明文。
4. 启动配置新增独立的凭证加密密钥读取路径：生产优先使用 Docker Secret 挂载文件 `ACCOUNT_CREDENTIALS_ENCRYPTION_KEY_FILE`；开发/测试通过显式配置注入。密钥缺失、格式错误或长度不正确时拒绝启动，不自动生成生产密钥。
5. 提供显式一次性迁移命令，将既有明文敏感字段转换为密文。迁移以批次和事务执行，支持重复运行，输出仅包含数量、错误和指纹，不输出凭证原文。
6. 预留密钥版本解析，后续轮换可配置旧密钥解密、新密钥写入，不需要改变账号业务接口。

## 安全边界

- 普通 API 响应继续执行现有凭证脱敏；原始凭证只在服务端受控网关路径短暂存在。
- Redis、日志、错误响应、备份和迁移输出均不得出现凭证原文。
- Docker socket、PostgreSQL、Redis 仍需保持内部网络隔离；本次代码改造不扩大公网暴露面。

## 验证要求

- 单元测试证明调度缓存序列化结果不含敏感字段。
- 单元测试证明凭证加密读写可保持原值，错误密钥和破损密文会失败关闭。
- 仓储测试覆盖创建、更新、OAuth 刷新、批量更新和旧明文兼容迁移。
- 调度服务测试证明从 Redis 取到的元数据账号会按 ID 回源并获得完整凭证。
- 运行定向 Go 测试、编译检查和全量 Go 测试；全量测试若超过执行窗口，记录实际命令和结果，不以未完成推断通过。

## 范围外

- 本次不接入外部 Vault/KMS 服务。
- 本次不改管理员导出接口权限模型，但会确保常规账号响应和缓存不泄露明文。
- 本次不在公网服务已停止的状态下启动生产容器或执行生产迁移。
