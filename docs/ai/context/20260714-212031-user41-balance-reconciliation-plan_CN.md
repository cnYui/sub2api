# user 41 支付宝补差余额核销计划

## 目标

按用户授权核销 `1510623550@qq.com/users.id=41` 因组合支付流程未续接而留存的 `74.00` 元余额。该用户的 `79 元订阅池` 已由管理员人工发放为 `user_subscriptions.id=110`，因此本次只处理重复保留的余额，不再次发放套餐。

## 会计处理

- 保留支付宝充值订单 `payment_orders.id=175` 的 `COMPLETED` 状态，因为支付宝已真实收款且回调成功。
- 保留原始充值兑换记录 `redeem_codes.id=24/type=balance/value=74`，保证支付审计链不被破坏。
- 通过正式管理员余额接口执行 `operation=subtract,balance=74`。
- 新增一条 `admin_balance=-74` 调整记录，备注关联充值订单 `175`、人工订阅 `110` 和本次核销原因。
- 用户余额预计从 `80.32` 变为 `6.32`；累计充值 `total_recharged=80.32` 保持不变。

## 执行步骤

1. 复核用户、充值订单、人工订阅和当前余额。
2. 备份 PostgreSQL，设置备份文件权限为 600，并用 `pg_restore -l` 验证可读。
3. 通过 `POST /api/v1/admin/users/41/balance` 执行减款，使用稳定幂等键避免重复核销。
4. 核对用户余额、累计充值、调整流水、订单状态和订阅状态。
5. 核对余额缓存与鉴权缓存失效情况，并验证服务健康。

## 回滚边界

若减款接口返回失败，不做直接 SQL 补写。若接口成功但结果不符合预期，通过同一管理员余额接口执行 `add 74`，并写明回滚原因；整库恢复需另行授权。
