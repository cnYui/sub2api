# 28 天订阅历史续费周窗口对齐计划

## 目标

维持公开 Codex 订阅的 `28 天有效期 + 每 7 天刷新` 契约，并修复历史 30 天等未对齐权益段提前续费后，周额度窗口跨越旧、新权益段的问题。

## 方案

- 订单快照和新权益段继续使用 28 天；不修改在售套餐的既有 28 天配置。
- 计算当前滚动周窗口时，以当前有效 `subscription_entitlement_period` 的 `starts_at` 作为窗口锚点，而不是永久使用订阅首次的 `weekly_anchor_at`。
- 权益段切换时，现有 `weekly_window_start` 与新窗口起点不一致，沿用既有维护逻辑将周用量归零并写入新窗口起点。
- 历史 30 天权益段保持其本身的尾段规则；新的 28 天权益段从自身起点获得四个完整周窗口，不读取旧段剩余用量。
- 用量事实和退款仍以权益段归属，不改变历史数据或运行库。

## 验证

- 先添加纯服务层回归：订阅整体锚点为旧起点、当前 28 天权益段从未对齐的旧到期点开始时，窗口必须从新权益段起点开始并给出完整周额度。
- 覆盖旧窗口用量不会带入新权益段的判断与维护路径。
- 回归已有四完整周窗口、订单快照和前端套餐展示测试。

## 边界

- 本轮只修改本地代码、测试和上下文文档，不操作数据库、容器、Nginx 或公网支付链路。
- 运行态历史权益段迁移和生产发布另行计划、备份与验证。
