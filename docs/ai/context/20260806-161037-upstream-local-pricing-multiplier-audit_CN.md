# 上游模型广场与本地计费倍率对照

## 对照口径

按管理员说明，`BILLING_FINAL_MULTIPLIER` 是本地汇率/利润隐藏倍率；本次只比较隐藏倍率之前的 `total_cost × groups.rate_multiplier` 与上游账号的 `resolved_rate_multiplier`。本地计费核心公式为：

```text
actual_cost = total_cost × groups.rate_multiplier × BILLING_FINAL_MULTIPLIER
```

## 当前生产状态

- 运行中的 `sub2api-official-18082` 容器实际为 `BILLING_FINAL_MULTIPLIER=18`，不是 15；部署文件和容器环境均为 18。
- PostgreSQL 当前 10 个活跃分组没有用户专属倍率覆盖。
- 上游账号元数据中的倍率与模型广场一致：Grok `0.9`、Claude Max `1.5`、Kiro `0.35`、GLM `3.5`、Kimi `3.5`、DeepSeek `4.9`、GPT `0.15/0.35/0.1`、GPT-Image-2 `1.0`。

## 基础单价差异

- GPT、Claude、Grok、DeepSeek 的主要输入/输出基础单价与上游页面一致，差异主要来自分组倍率。
- 本地部署的 GLM 动态目录为缓存写入 `$1.00/M`、缓存读取 `$0.28/M`；上游页面为写入 `$0.00/M`、读取 `$0.26/M`。即使修正分组倍率，GLM 缓存价格仍不会完全一致。
- 本地 Kimi K2.6 动态目录为 `$0.954/$3.961/$0.161`，上游页面为 `$0.95/$4.00/$0.16`，属于小数级目录差异；Kimi K2.5 已由本地策略固定到 `$0.60/$3.00/$0.098`。
- 本地没有与上游模型广场完全对应的 Gemini、Qwen、官方 API 独立分组，不能宣称全量价格一致。

## 名称风险

当前 GLM、Kimi、DeepSeek 的分组名称仍是历史的“0.2 折/0.5 折/0.7 折”，但实际本地倍率为 `1.0`；名称不是实时计费依据，容易误导用户。
