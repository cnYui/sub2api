# 充值订阅与流量卡手续费实现计划

## 目标

购买页对余额套餐和流量卡都明确展示并收取配置的 1% 手续费；手续费只增加支付金额，不减少套餐到账额度或流量卡额度。

## 现状与决策

- 服务端 `PaymentService.CreateOrder` 已从 `RECHARGE_FEE_RATE` 读取手续费，并把余额套餐、流量卡的商品标价传入统一的支付金额计算函数。
- 购买页确认步骤已有手续费行，但目录卡仍只展示商品标价，容易让用户误以为未收费。
- 新增前端金额工具函数，目录卡与确认步骤共用“手续费向上取整到分”的计算规则。
- 服务端仍是最终权威；前端提交商品原价，服务端根据数据库商品和当前配置重新计算 `pay_amount`。

## 实施步骤

1. 先用 Vitest 写金额工具函数的失败测试，覆盖余额套餐、流量卡和 0% 兼容行为。
2. 新增金额工具函数并替换 `PurchaseShopView.vue` 的内联计算。
3. 目录卡价格改为实付金额，明细同时展示标价和手续费；确认页保留标价、手续费和实付三行。
4. 增加 Go 服务层回归测试，锁定余额套餐和流量卡均按配置手续费计算网关金额。
5. 运行前端定向测试、后端定向测试、前端类型检查和构建；记录结果并更新 `AGENTS.md` 的上下文索引。

## 验收标准

- 标价 ¥29 的余额套餐显示手续费 ¥0.29，实付 ¥29.29，到账权益仍按原套餐配置。
- 标价 ¥2 的流量卡显示手续费 ¥0.02，实付 ¥2.02，流量卡额度仍按原配置。
- 服务端订单 `amount` 保持商品标价，`pay_amount` 为含手续费金额，`fee_rate` 快照为 1。
- 手续费配置为 0 时，页面和服务端均回到原价。
