# 退款真实支付准入收紧

## 结论

退款对象现在必须同时满足：余额套餐订单、非管理员发放、实付金额大于 0、存在支付完成时间和支付平台交易号。流量卡、旧普通余额订单、管理员发放订单、兑换码兑换额度和零金额记账订单均不可退款。

## 实现

- 后端统一使用 `validateRealPaidBalancePackageOrder`，覆盖用户申请、管理员退款准备、实际网关调用、退款报价和待确认退款查询。
- 删除无支付交易号时直接返回退款成功的兼容路径，避免没有真实支付却被标记为退款成功。
- 用户订单页、管理员订单表、管理员订单详情和管理员订单处理页均只显示真实支付余额套餐的退款操作。
- 新增后端凭证矩阵测试和前端退款入口判断测试。

## 验证说明

前端类型检查和定向测试需在依赖完整的 `frontend` 工作区执行。后端带 `unit` 标签的全包测试当前仍受仓库既有缺少测试辅助函数影响，具体错误在交付说明中列出；本次新增测试本身不依赖这些缺失辅助函数。
