# 10 USD 流量卡“我的订阅”显示与可用性排查计划

## 背景

- 用户反馈：某用户前端“我的订阅”页面看不到此前发放的两张 10 USD 流量卡。
- 已有上下文 `20260703-095030-traffic-card-10usd-verification-result_CN.md` 显示：2026-07-02 批次 10 USD OpenAI 流量卡已覆盖 52 个未删除用户；流量卡计费链路已用无订阅用户真实请求验证可扣费。
- 需要进一步确认：
  - 前端“我的订阅”页面是否本来就没有渲染流量卡。
  - 流量卡只是显示问题，还是实际不可用。
  - 可用 `2799523972@qq.com / 123123` 真实登录浏览器查看页面。

## 排查原则

- 先查根因，不先做修复。
- 分离三条链路：
  - 数据库事实：用户是否持有 10 USD 流量卡，剩余额度是否正常。
  - 后端 API：前端页面调用的接口是否返回流量卡数据。
  - 前端渲染：页面是否读取并展示对应字段。
- 不记录完整 API Key、内部 token、SMTP 密码或 HMAC secret。

## 计划

1. 读取“我的订阅”页面、订阅 store、订阅 API、支付/流量卡类型定义，确认页面数据来源。
2. 查询公网运行态数据库中目标用户和 `2799523972@qq.com` 的流量卡、订阅、API Key 状态。
3. 直接请求当前页面使用的用户侧 API，确认响应是否包含流量卡信息。
4. 用浏览器真实登录 `2799523972@qq.com`，打开“我的订阅”页面观察真实显示。
5. 如确认只是前端未渲染：
   - 先补一个能暴露缺陷的前端测试。
   - 最小改动让“我的订阅”页面展示 OpenAI/GPT 流量卡汇总和明细。
6. 用测试、API 请求和浏览器页面复验，并新增结果上下文。

## 风险与边界

- 若用户仍有 active 订阅且日额度未耗尽，API 请求优先走订阅计费，流量卡不会被扣；这不代表流量卡不可用。
- 验证“能否使用”时优先用已有无订阅/超限用户证据，避免为了验证而改动目标用户订阅状态。
- 浏览器登录只用于查看页面，不进行支付、重置密码或破坏性操作。
