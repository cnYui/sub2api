# xinlise@gmail.com 退款失败后购买阻塞清理计划

## 背景

`xinlise@gmail.com` 的订单 `payment_orders.id=140` 自动退款失败，用户反馈已手动取消订阅，但仍无法再次购买。需要定位购买拦截原因，并让该用户能够重新购买，同时取消当前所属套餐。

## 处理原则

- 先只读定位购买拦截条件，不猜测。
- 写库前备份运行态 Postgres。
- 仅处理该用户相关的订阅/套餐状态和必要缓存。
- 不执行支付退款，不伪造支付成功，不改 usage 历史。

## 步骤

1. 读取购买保护实现，确认拦截条件。
2. 只读查询 `users`、`user_subscriptions`、`user_allowed_groups`、`api_keys`、`payment_orders`。
3. 如果发现仍有未删除未过期 active 订阅或自动分组归属，先备份运行态库。
4. 最小写库取消该用户当前套餐归属，并清理相关 Redis 账单缓存。
5. 复核购买保护查询结果应不再命中。

## 不做

- 不改订单退款状态，除非确认它是购买阻塞根因。
- 不删除 usage_logs。
- 不重启服务、不发布代码。
