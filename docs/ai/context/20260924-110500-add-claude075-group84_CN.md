## 关键发现：这把 key 就是账号 #1166 的 key

把这把 key 的 `/v1/usage.daily_usage` 与我方 `usage_logs` 按账号逐日对比，和 #1166（分组 71 `Claude0.78倍率`，09-23 因上游号池不可用而停用）完全吻合：

| 日期 | 上游这把 key | 我方 #1166 |
| --- | --- | --- |
| 08-26 | 577 次，输入 587,606 / 输出 4,018,224 | 577 次，587,606 / 4,018,224 |
| 09-20 | 2 次，10 / 2 | 2 次，10 / 2 |
| 09-23 | 1 次，12 / 128 | 1 次，12 / 128 |

其余日期请求数偶有 ±2~4 的差（失败请求两边记法不同），token 基本一致。结论：**同一把 key**，而且上游这两天恢复了（71 停用时 6 个模型全挂，今天 8 个全通）。

所以没有新建账号，而是**直接把 #1166 绑到新分组**：key 已经加密存在 #1166 里，不需要任何人再粘贴一遍，也避免了两个账号共用一把 key 却各算各的并发。
