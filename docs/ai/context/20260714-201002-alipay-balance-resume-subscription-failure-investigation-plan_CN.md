# 支付宝充值续接余额购买套餐失败调查计划

## 目标

只读定位 2026-07-13 用户在余额不足场景下，通过支付宝充值后仍未成功获得新套餐的真实失败点，区分外部支付、余额入账、自动续接购买、套餐发放和事务提交各阶段。

## 已知约束

- 当前产品历史设计不支持把单笔商品订单直接拆成“支付宝部分 + 余额部分”；更可能的实现是先创建支付宝余额充值订单，充值成功后再续接余额购买商品。
- 本轮仅诊断，不修改订单、用户余额、订阅、支付配置、数据库、Redis、容器或代码。
- 以运行态 PostgreSQL、容器日志和当前发布代码互相印证，不仅依据前端提示判断。

## 调查步骤

1. 查询 2026-07-13 全部支付宝余额充值订单及其关联用户、金额、状态、回调时间和后续商品订单，锁定“充值完成但未发套餐”的候选链路。
2. 按候选订单时间窗口读取 `sub2api-candidate` 日志，确认请求、回调、余额续接接口和具体错误信息。
3. 核对候选用户的余额流水、支付审计、套餐订单、订阅记录和当前余额，判断事务是否整体回滚或只完成了前半段。
4. 回溯当前前后端续接实现与套餐履约事务边界，比较成功链路和失败链路，形成单一根因结论。

## 输出

- 明确失败用户、订单和时间点。
- 明确支付宝是否实际成功、余额是否入账、商品订单是否创建、套餐是否发放。
- 给出根因、影响范围和后续修复方向；未经用户授权不实施修复。
