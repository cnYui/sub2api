# Available Channels 页面收敛为模型价格页设计

## 背景

当前 `/available-channels` 已新增顶部价格卡，用于展示 `gpt-5.4`、`gpt-5.5` 和生图价格。但页面仍保留搜索框、刷新按钮和下方渠道表，信息目标变成了混合态：

- 标题仍是“可用渠道”。
- 顶部在表达“价格”。
- 下方表格在表达“渠道列表”。

用户当前需求很明确：这个页面不再承担渠道浏览职责，只保留价格展示，标题和描述也同步改成“模型价格”。

## 目标

1. `/available-channels` 页面只展示模型价格相关内容。
2. 页面标题改为“模型价格”。
3. 页面描述改为围绕当前账号可用模型与生图价格。
4. 保留现有价格数据来源，不改后端接口、路由、权限、计费逻辑。

## 非目标

- 不修改 `/api/v1/channels/prices`、`/groups/available` 或任何后端逻辑。
- 不调整侧边栏路由路径 `/available-channels`。
- 不新增独立页面或新路由。
- 不恢复或重做渠道表的空态展示。

## 设计决策

### 方案选择

采用最小改动方案：继续复用 `frontend/src/views/user/AvailableChannelsView.vue` 和现有价格组装逻辑，只删除与“渠道浏览”相关的 UI 和状态。

不选新建 `ModelPricesView`，因为：

- 这次只是页面职责收敛，不是信息架构重建。
- 现有价格计算逻辑已经稳定，复用更安全。
- 新建页面会引入额外路由和测试迁移，没有收益。

### 页面结构

页面保留：

- `AppLayout`
- `TablePageLayout`
- 价格卡 section

页面移除：

- 搜索框
- 刷新按钮
- 渠道表组件 `AvailableChannelsTable`
- 搜索过滤相关状态和计算
- 渠道表列名相关计算

`loadChannels()` 仍在 `onMounted` 时执行，因为价格卡仍依赖：

- `/channels/prices`
- `/groups/available`
- 现有渠道模型列表作为价格回退来源

### 文案

`availableChannels.title` 改为：

- 中文：`模型价格`
- 英文：`Model Prices`

`availableChannels.description` 改为围绕“查看当前账号可用模型与生图价格”。

## 测试策略

采用当前仓库已有的 `vitest` 单测方式，覆盖两个点：

1. 价格卡仍能展示 GPT 与生图价格。
2. 页面不再渲染渠道表占位。

## 风险与控制

主要风险是移除表格后误删了价格卡依赖的数据加载逻辑。控制方式：

- 只删除表格与搜索相关代码，不动价格组装函数。
- 先改测试，让它明确断言“不再存在渠道表”。
- 跑目标测试和前端 build，确认页面结构收敛但编译链路不受影响。
