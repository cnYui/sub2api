# 手机端触屏按钮无法点击排查计划

## 背景

用户反馈当前网页在手机端响应式时，部分按钮触屏无法点击。已按手机视口打开本地前端 `http://127.0.0.1:5174/` 初步验证：

- 未登录首页 `/home` 的「立即登录」链接可正常点击。
- 登录页表单按钮中心点命中自身或内部 SVG，没有发现遮罩覆盖。
- 可疑区域集中在登录后的 `AppLayout`：移动侧栏、遮罩、Header、用户下拉和页面内容之间存在层级竞争。

## 根因假设

`AppSidebar` 中移动菜单打开时：

- 侧栏 `.sidebar` 是 `z-40`。
- 移动遮罩是 `z-30`。
- `AppHeader` 也是 `z-30`。

遮罩和 Header 层级相同，在移动触屏路径下容易出现命中顺序不稳定：部分区域可能由 Header 或遮罩截获，导致用户以为按钮无法点击。移动菜单关闭后如果状态或过渡处理不一致，也可能短时间拦截主内容点击。

## 设计

只调整布局层级，不改业务逻辑：

- Header 在常规页面保持 `z-30`。
- 移动遮罩提升到 Header 之上、侧栏之下，例如 `z-[35]`。
- 侧栏保持最高的移动层级，确保菜单项可点。
- 遮罩只在 `mobileOpen=true` 时存在，关闭后不保留任何可拦截点击的元素。

## 测试计划

- 新增或扩展 `AppSidebar` 源码级测试，断言移动遮罩层级高于 Header 且低于 Sidebar。
- 使用浏览器手机视口验证：
  - 打开用户态页面。
  - 菜单按钮可打开侧栏。
  - 侧栏菜单项中心点没有被遮罩覆盖。
  - 关闭菜单后页面主按钮中心点没有被遮罩覆盖。

## 取舍

- 不引入新组件或全局 overlay 管理器，避免扩大改动面。
- 不调整桌面布局和业务路由。
- 如果验证发现还有其他页面级浮层截获点击，再单独按具体组件修复。
