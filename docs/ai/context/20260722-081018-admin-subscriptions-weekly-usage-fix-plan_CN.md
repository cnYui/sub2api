# 管理订阅页周用量展示修复计划

## 背景

`/admin/subscriptions` 在公共 Codex 周滚动额度切换后仍展示“每日”用量与自然日重置倒计时，导致历史日额度超额的两个本地账号继续显示红色旧用量。

## 目标

- 管理端订阅列表对公共 Codex 订阅展示当前滚动周窗口用量、有效周额度与后端返回的周窗口重置时间。
- 本地开发库只处理 `xunskyler@gmail.com` 与 `luzhiyuan2026@163.com` 两个账号的旧日额度展示残留，让今天页面展示抵扣后的合理额度，后续按周窗口正常刷新。
- 不操作公网、生产数据库、Nginx、Cloudflare 或 CLIProxyAPI。

## 实施步骤

1. 核对本地 API/数据库里两个账号的订阅、分组、权益段、周窗口字段和旧日窗口字段。
2. 修复前端或后端列表 DTO 的周额度判定，使公共 Codex 订阅不再落入 daily 展示分支。
3. 对两个指定账号写入本地开发库的合理周窗口/日窗口事实，并保留既有债务审计幂等记录，不重复扣减有效期。
4. 补充或调整测试，覆盖管理订阅页公共 Codex 显示每周用量和周重置时间。
5. 运行后端与前端验证，重建并重启本地开发服务。

## 风险与边界

- 只改本地开发环境数据；本地数据修复不是生产迁移依据。
- 额度判断以后端精确字段为准，前端只展示，不参与计费判断。
- 若发现缺失权益段或字段为空，优先修数据/查询根因，不在前端硬编码套餐额度。
