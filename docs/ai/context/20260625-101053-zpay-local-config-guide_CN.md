# ZPay 本地收款配置说明

## 配置原则

- ZPay 作为 EasyPay 协议服务商接入，不新增独立 `zpay` provider。
- 商户密钥只应写入运行态数据库中的支付服务商配置，不写入代码、文档、提交或日志。
- Sub2API 继续负责订单、用户余额/订阅、回调验签、查单和履约。

## 后台配置

进入管理后台：

1. 设置 → 支付设置 → 启用支付。
2. 服务商管理 → 新增服务商。
3. 服务商类型选择 `EasyPay`。
4. 名称建议填写 `ZPay` 或 `ZPay EasyPay`。
5. 支持方式选择：
   - `alipay`
   - `wxpay`（如 ZPay 商户已开微信通道）
6. API 基础地址填写：`https://zpayz.cn`
7. PID 填写用户提供的 ZPay 商户号。
8. PKey 填写用户提供的 ZPay 商户密钥。
9. 支付模式建议先选择 `二维码`，完成真实小额支付验证后再视需要切换 `弹窗`。
10. 保存并启用服务商实例。

## 前台可见支付方式

在支付设置中继续配置：

- 支付宝来源选择 `EasyPay 支付宝`
- 微信支付来源选择 `EasyPay 微信支付`（如启用微信通道）

否则服务商实例即使启用，用户购买页也不会暴露对应支付按钮。

## 验证方式

建议先用 1 元以内订单做真实链路验证：

1. 用户端创建支付宝订单。
2. 确认页面出现 ZPay 返回的二维码内容或二维码图片。
3. 完成支付。
4. 确认 `/api/v1/payment/webhook/easypay` 返回 `success`。
5. 确认订单进入 `PAID/RECHARGING/COMPLETED`，订阅或流量包完成发放。
6. 如回调延迟，可用订单页主动查单验证。

## 本次代码补齐点

ZPay `mapi.php` 可能只返回 `img` 字段作为二维码图片地址。本次实现新增 `qr_image_url` 响应通道，前端会直接展示该图片，不再把图片 URL 误当作二维码内容重新生成。
