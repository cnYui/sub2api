# 公网中转站当前活跃请求只读排查计划

## 目标

- 判断当前公网中转站是否仍有人在使用、是否还有 API 请求进入。
- 区分控制台/页面访问与真正的 `/v1/*`、裸 `/responses` 等模型请求。

## 范围

- 只读检查 `sub2api-candidate`、`sub2api-candidate-postgres`。
- 不读取、不输出完整 API Key、内部 token 或其他敏感字段。
- 不修改公网应用、DB、Redis、nginx 或容器运行态。

## 排查路径

1. 查询容器健康与数据库当前时间。
2. 从 `usage_logs` 统计最近 1/5/15/60 分钟成功记账请求数量、用户数、最新请求时间。
3. 按用户、模型、入口、分钟聚合近期成功用量，确认是谁在实际发模型请求。
4. 从 `sub2api-candidate` 日志查看最近 5/15 分钟网关请求与错误，判断是否有进入但尚未完成或未记账的请求。
5. 保存结果上下文并给出“还有没有人在用”的明确结论。
