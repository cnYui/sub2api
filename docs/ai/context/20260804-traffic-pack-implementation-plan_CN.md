# 2026-08-04 流量卡购买与余额兜底实现计划

## 目标

将 18080 的三个 GPT 流量卡接入 18082 `/purchase` 页面，形成真实的创建订单、ZPay 支付、到账、计费和退款闭环。

## 约束

- 流量卡有效期固定为购买到账时刻起 28 天；不同订单分别以各自到账时间计算。
- 流量卡额度按美元额度进入用户可用计费体系；普通余额不足时按最早到期顺序扣除流量卡。
- 扣费必须原子执行，最后一次允许准确扣到 0，额度不足以覆盖本次请求时拒绝请求，不产生负额度。
- 订单金额、订单状态、到账额度和退款金额由服务端数据库与支付服务商结果决定。
- 退款绑定创建订单时保存的支付服务商实例；退款报价取时间使用比例与额度使用比例的最大值。
- 退款成功只撤销当前订单对应的流量卡额度，不影响其他订单的额度。

## 实现范围

1. 新增 `traffic_packs`、`user_traffic_credits` 和 `traffic_credit_ledger` 表及默认三档套餐。
2. 接入订单类型 `traffic_pack`，服务端从数据库读取套餐价格与额度并保存订单快照。
3. 支付成功后幂等发放额度，展示用户流量卡余额和明细。
4. 计费预检与扣费在普通余额不足时切换到流量卡，按最早到期优先扣除。
5. 用户订单页显示流量卡订单并支持报价、提交退款和失败重试。
6. 微信支付恢复流程保留流量卡 ID。

## 验证

- Go 格式化、服务层和仓储层单元测试。
- 前端类型检查和支付流测试。
- 数据库迁移后检查三档套餐均为 28 天。
