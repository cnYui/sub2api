# 订阅退款比例反转设计

## 背景

现有订阅退款报价按 `订单本金 × (1 - 已用额度比例)` 计算，已用 25% 时退 75%。业务确认该数值应视为平台保留金额，用户实际退款必须为订单本金减去该金额。

## 决策

订阅退款的唯一事实源改为：

```text
已用比例 = clamp(已用额度 USD / 权益周期总额度 USD, 0, 1)
平台保留金额 = 订单本金 × (1 - 已用比例)
用户退款金额 = 订单本金 - 平台保留金额 = 订单本金 × 已用比例
```

示例：订单本金 29 元、已用比例 25% 时，平台保留 21.75 元，用户退款 7.25 元。

手续费仍不退：退款本金继续使用 `payment_orders.amount`，不使用 `pay_amount`；订阅订单的网关退款金额继续等于退款本金，不按实付金额比例放大。

## 影响范围

- `calculateSubscriptionRefundQuoteWithClient` 只修改 `estimated_refund_amount` 的计算公式。
- 用户报价、管理员报价、管理员退款、用户余额退款、用户支付宝退款和事务内重算均继续消费同一个报价，不各自计算。
- 退款依据仍记录已用额度、已用比例和订单本金，历史已完成退款不回写。

## 验证

- 0% 已用：不可自动退款。
- 25% 已用：29 元本金退款 7.25 元。
- 100% 已用：29 元本金全额退款。
- 覆盖管理员事务内重算、支付宝自动退款、余额自动退款，确认金额和持久化退款依据一致。
