# 超额订阅按 72 USD/周扣减有效期计划

## 范围

仅处理本地开发库 `sub2api-postgres-dev` 中两个已超过当前 15 USD 日额度的 `codex-pool-19-usd` 活跃订阅；不触碰公网候选环境、Nginx、Redis 之外的任何运行态。

## 业务规则

- 周额度固定为 72 USD，日均抵扣能力为 `72 / 7 = 10.2857142857 USD`。
- 扣减天数为 `floor(超额 USD / (72 / 7))`，不向上取整。
- 扣减 `user_subscriptions.expires_at`，并同步截断覆盖新到期日的 active `subscription_entitlement_periods`，避免 Dashboard 权益读模型、退款校验与订阅事实出现两个到期时间；不修改历史 `usage_facts`、`usage_logs`、日/周用量或订单金额。
- 更新完成后删除这两个用户的订阅 Redis 缓存，使下一次资格校验立即读取新到期时间。

## 执行与回滚

1. 导出仅这两条订阅、关联用户和分组的 SQL 备份，并通过独立 `psql` 会话验证可读。
2. 在一个事务中以 ID、用户邮箱、原始 `expires_at` 三重条件更新订阅到期时间，并仅截断覆盖目标日期的 active 权益段；对不满足预期行数的情况抛错回滚，避免并发或对象误匹配。
3. 删除 `billing:sub:<user_id>:<group_id>` Redis 键，并读取数据库复核目标值。
4. 如需回滚，使用备份中的原始 `expires_at` 按订阅 ID 恢复，并再次删除相同缓存键。
