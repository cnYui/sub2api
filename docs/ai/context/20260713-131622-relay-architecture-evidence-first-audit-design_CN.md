# 中转站架构证据优先审计设计

## 目标

对 `Codex -> Cloudflare -> cloudflared/Nginx -> sub2api -> CLIProxyAPI -> 上游模型` 的真实运行链路做只读审计，回答安全隔离、流式性能、重试计费一致性、可观测性、容量、发布运维和灾难恢复问题，并输出可执行的低成本单机方案与跨主机生产级 HA 方案。

## 方案比较

1. 仅依据历史文档和仓库配置：成本最低，但无法识别运行态漂移，不能满足“证据优先”。
2. 运行态只读取证加源码/配置交叉验证：能确认当前链路、协议、监听、身份、超时和单点，风险可控，作为本轮方案。
3. 主动故障注入与高并发压测：证据最强，但会影响生产流量、可能产生上游费用，本轮明确禁止，只输出隔离环境测试矩阵。

## 审计边界

- 允许：读取 DNS、Cloudflare 可公开验证信息、进程、监听端口、Nginx 生效配置、Docker 元数据、证书公开部分、源码、非敏感配置字段、健康状态、聚合日志和资源指标。
- 禁止：修改配置、重启或 reload、清缓存、写数据库、触发真实模型高费用请求、生产并发压测、输出 API Key、Cookie、Token、数据库密码、证书私钥或完整请求正文。
- 外部事实：Cloudflare 协议、超时和 Tunnel 能力只采用官方文档，并记录查询日期与适用产品范围。

## 证据等级

- **已证实**：当前运行命令、有效配置、源码或协议探测直接支持；白皮书附证据位置和时间。
- **高概率推断**：多个独立证据一致，但缺少控制面或端到端可重复验证；同时列出推断链和反证条件。
- **待验证**：缺少访问权限、指标、日志字段或需要破坏性/付费测试；不得写成现状结论。

## 分层方法

### 边缘与入口

核验 DNS 解析、Cloudflare 代理状态线索、`cloudflared` 进程及实际 ingress、宿主机公网监听、防火墙、Nginx `listen`/real IP/限流/TLS/HTTP 版本。重点判断 Tunnel 已启用后是否仍存在旁路公网入口，而不是重复建议引入 Tunnel。

### 本地代理与应用边界

核验 Nginx 到 sub2api、sub2api 到 CPA 的地址、协议、证书校验、内部凭据、Docker 网络和宿主机端口暴露。对同机 loopback HTTP/mTLS 按威胁模型评估维护收益，不把“全链路加密”当作形式目标。

### 流式与一致性

从请求上下文取消、响应读取方式、Flush、缓冲、超时、连接池、重试点、账号切换、幂等键、usage 终态和错误映射追踪完整数据流。明确首 Token 前后的重试边界，首 Token 后不承诺无损切换。

### 资源、HA 与运维

核验实例数、进程托管、健康检查、持久化、文件描述符、连接池、端口与 TIME_WAIT、Docker Desktop 资源、PostgreSQL/Redis 依赖和发布方式。用 Little's Law 建立容量模型，但不伪造缺失的流量分布数据。

## 交付结构

1. 执行摘要和事实基线。
2. “已验证当前拓扑”与“目标拓扑”两张 Mermaid 图。
3. 风险清单、分段协议表、超时预算表、限流矩阵。
4. 安全、性能、流式正确性、可观测性、容量、HA、运维和 DR 分析。
5. Nginx 最小配置差异，所有值区分“当前值”和“建议值”。
6. 低成本单机加固版与跨主机生产级 HA 版。
7. 24 小时、7 天、30 天、90 天路线图。
8. 隔离环境故障注入与验收矩阵。

## 验收标准

- 每个关键判断均标记证据等级，并能追溯到命令、配置、源码、日志或官方文档。
- 不泄漏任何完整凭据或用户正文。
- 不把历史文档写成当前事实，不把 Cloudflare 客户端侧 HTTP/3 等同于所有内网跳点协议。
- 不建议首 Token 后透明重试，不把 CPA 共享内部 Key 当作最终用户身份。
- 所有优化包含影响、成本、回滚和验收方法。
