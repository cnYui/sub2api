# 18085 SMTP 运行态配置同步到 18084 设计文档

时间：2026-06-28 15:32 JST

## 背景

公网 18084 当前应用容器 `sub2api-candidate` 已运行最新修复镜像：

```text
sub2api-candidate:20260627-221441-traffic-card-fix
127.0.0.1:18084->8080
```

但新用户注册邮箱验证码仍无法发送。排查结果见：

```text
docs/ai/context/20260628-152717-public-18084-email-verify-smtp-not-configured-diagnosis_CN.md
```

关键事实：

- 18084 代码和镜像没问题。
- 18084 使用的数据库是 `sub2api-candidate-postgres`。
- 18084 数据库 `settings` 表中 SMTP 相关值为空。
- 18085 使用的数据库是 `sub2api-smtp-test-postgres`。
- 18085 数据库 `settings` 表中 Gmail SMTP 已配置并验证过能发信。
- SMTP 配置是运行态 DB settings，不属于 Docker 镜像内容；重新构建镜像不会自动修复 18084 的空 SMTP 配置。

## 目标

把 18085 测试库中已经验证可用的 SMTP 运行态配置，同步到 18084 公网候选库，使公网新用户注册验证码邮件可以正常发送。

## 非目标

- 不重新构建镜像。
- 不替换、重启或重建 Postgres/Redis。
- 不执行 `docker compose down`。
- 不修改用户、订阅、API Key、订单、支付配置、流量卡余额。
- 不在文档、日志、命令输出或提交中记录 SMTP 密码明文。
- 不把 18085 整库覆盖到 18084。

## 数据范围

只同步 `settings` 表中的以下键：

```text
smtp_host
smtp_port
smtp_username
smtp_password
smtp_from
smtp_from_name
smtp_use_tls
```

可选只读核对，不主动修改：

```text
registration_enabled
email_verify_enabled
password_reset_enabled
```

当前预期这些开关在 18084 已为 `true`，所以不需要同步。

## 架构选择

### 方案 A：从 18085 读取 SMTP settings，再 upsert 到 18084

流程：

1. 从 `sub2api-smtp-test-postgres` 只读导出上述 SMTP 键值到临时文件。
2. 临时文件权限设为 `0600`。
3. 不打印临时文件内容。
4. 将临时文件通过 `psql` 导入 `sub2api-candidate-postgres`。
5. 对 `settings` 表执行按 key 的 upsert。
6. 删除临时文件。
7. 重启 18084 应用容器或调用配置刷新能力，让进程重新读取 SMTP settings。
8. 发一封公网验证码做验证。

优点：

- 不需要人工重新输入 Gmail App Password。
- 同步范围最小。
- 可保留 18084 现有公网库全部业务数据。

风险：

- 临时文件短暂包含 SMTP 密码明文，必须限制权限并执行后删除。
- 如果 18085 的 SMTP 配置已经过期，18084 同步后也会发信失败；需要通过真实验证码验证。

### 方案 B：通过后台管理页在 18084 重新配置 SMTP

流程：

1. 管理员登录 18084 公网后台。
2. 在 SMTP 设置页手动填入 Gmail SMTP 和 App Password。
3. 保存后发送测试邮件或注册验证码验证。

优点：

- 不需要命令行处理密码。
- 更符合长期运营操作习惯。

风险：

- 需要用户手动提供或复制 App Password。
- 容易误填字段。
- 不利于快速恢复。

## 推荐方案

推荐执行方案 A。

理由：

- 18085 的 Gmail SMTP 已经在本机测试库验证过可发信。
- 18084 当前只是缺少同一组运行态 settings。
- 同步 7 个 SMTP 键即可，不需要动镜像、数据库结构或业务数据。

## 执行设计

### 1. 前置只读核对

核对两套库的非敏感 SMTP 状态：

```text
sub2api-candidate-postgres:
  smtp_host=[EMPTY]
  smtp_username=[EMPTY]
  smtp_from=[EMPTY]
  smtp_password=[EMPTY]

sub2api-smtp-test-postgres:
  smtp_host=smtp.gmail.com
  smtp_username=[CONFIGURED]
  smtp_from=[CONFIGURED]
  smtp_password=[CONFIGURED]
```

核对公网应用健康：

```text
curl -fsS http://127.0.0.1:18084/health
curl -fsS http://127.0.0.1:8080/health
curl -fsS https://api.aaccx.pw/health
```

### 2. 备份 18084 SMTP 当前值

只备份 SMTP 相关 settings 到本地加权限临时文件：

```text
deploy/backups/YYYYMMDD-HHMMSS-18084-smtp-settings-before-sync.tsv
```

该文件可能包含密码明文。如果当前 18084 密码为空，风险较低；仍按敏感文件处理，不提交，不在文档中展开内容。

### 3. 同步 18085 SMTP 值到 18084

同步语义：

```sql
insert into settings (key, value, created_at, updated_at)
values (...)
on conflict (key) do update
set value = excluded.value,
    updated_at = now();
```

如果 `settings` 表没有 `created_at/updated_at` 或字段名不同，执行前按实际表结构调整。

### 4. 刷新 18084 应用配置

优先选择轻量方式：

1. 如果邮件服务每次发送都会从 `settings` 动态读取 SMTP，则无需重启。
2. 如果存在进程内缓存，则只重启 `sub2api-candidate` 应用容器。

重启约束：

- 只重启 `sub2api-candidate`。
- 不停止 `sub2api-candidate-postgres`。
- 不停止 `sub2api-candidate-redis`。
- 不修改 nginx。
- 保留端口 `127.0.0.1:18084->8080`。

## 验证设计

### 1. 设置核对

同步后查询 18084 非敏感状态：

```text
smtp_host=smtp.gmail.com
smtp_port=587
smtp_username=[CONFIGURED]
smtp_password=[CONFIGURED]
smtp_from=[CONFIGURED]
smtp_from_name=AACCX
smtp_use_tls=false
```

### 2. 真实发信验证

使用一个未注册邮箱调用公网接口：

```text
POST https://aaccx.pw/api/v1/auth/send-verify-code
```

或本机 nginx Host 路由：

```text
POST http://127.0.0.1:8080/api/v1/auth/send-verify-code
Host: aaccx.pw
```

验证标准：

- HTTP 返回 200。
- `sub2api-candidate` 日志出现验证码任务入队。
- EmailQueue worker 不再报 `EMAIL_NOT_CONFIGURED`。
- 日志出现成功发送或 SMTP 成功响应。

### 3. 回归健康检查

```text
curl -fsS http://127.0.0.1:18084/health
curl -fsS http://127.0.0.1:8080/health
curl -fsS https://api.aaccx.pw/health
```

## 回滚设计

如果同步后 SMTP 发送失败，按失败类型处理：

- `EMAIL_NOT_CONFIGURED`：说明同步未生效，重新核对 18084 settings 或重启应用。
- SMTP authentication failed：说明 18085 中的 App Password 可能过期或不适用于公网配置，需要用户重新提供 App Password。
- 网络或 TLS 错误：核对 `smtp_port`、`smtp_use_tls` 和 Gmail SMTP 连接策略。

如需回滚配置：

1. 使用执行前备份的 18084 SMTP settings 恢复 7 个 key。
2. 只重启 `sub2api-candidate` 应用容器。
3. 再跑健康检查。

## 安全要求

- 不在终端输出 SMTP 密码。
- 不把包含 SMTP 密码的临时文件加入 git。
- 临时文件用完立即删除，除非用户明确要求保留加权限备份。
- 文档中只写 `[CONFIGURED]` 或 `[EMPTY]`。
- 不在日志摘要里写 Gmail App Password 明文。
