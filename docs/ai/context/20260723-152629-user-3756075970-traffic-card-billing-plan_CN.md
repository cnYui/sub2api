# 用户 3756075970@qq.com 仅流量卡计费验证计划

## 目标

验证用户 `3756075970@qq.com` 在没有有效订阅套餐、只有流量卡的情况下，是否能通过自己的 Sub2API Key 正常调用公网 `/v1`，并按流量卡产生真实扣费事实。

## 范围

- 当前公网事实源：以运行态容器和数据库为准，优先核对 `sub2api-candidate` / `sub2api-candidate-postgres`。
- 用户范围：只读取该用户、其 API Key、订阅状态、流量卡余额和本次请求产生的 usage 事实。
- API 范围：使用该用户自己的 active API Key 发起一次低成本 `/v1/responses` 测试；必要时先调用 `/v1/models` 验证认证链路。

## 安全边界

- 不把完整 API Key、内部 token、HMAC、支付密钥写入文档、命令输出或回复。
- 测试请求会写入真实 usage/billing 事实，并消耗极小额度；这是本次要验证的行为。
- 测试前保存该用户相关账务行的只读快照，便于事后比对；不自动回滚真实测试用量。
- 不修改订阅、余额、流量卡、Redis、容器、Nginx 或上游账号池配置。

## 验证步骤

1. 核对当前运行态健康、容器和数据库连通性。
2. 查询该用户是否存在有效订阅、是否存在 active API Key、流量卡可用余额。
3. 生成本次测试 marker，记录请求前余额、用量和最近 ledger。
4. 使用该用户 Key 调用公网 `/v1/responses` 的低成本文本请求。
5. 通过 `x_client_request_id` 核对 `usage_facts`、`usage_logs`、流量卡余额/流水增量。
6. 输出结论：能否使用、是否按流量卡真实扣费、是否存在异常或后续风险。
