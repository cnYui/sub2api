# 2026-06-28 18084 DB 克隆到 18080 main-preview 执行计划

## 目标

把当前公网候选库 `sub2api-candidate-postgres` 只读 dump 出来，覆盖导入到本地蓝绿测试库 `sub2api-main-preview-postgres`，再启动 `sub2api-main-preview`，让当前本机 `main` 镜像自动应用本地新增迁移。

## 边界

- 18084 只允许只读 `pg_dump` 和只读查询。
- 禁止停止、删除、重建、重命名 `sub2api-candidate*`。
- 禁止写入 `sub2api-candidate-postgres` 或 `sub2api-candidate-redis`。
- 禁止修改 nginx、Cloudflare Tunnel 或 `8080 -> 18084`。
- 允许覆盖 `sub2api-main-preview-postgres`。
- 允许清空 `sub2api-main-preview-redis`，避免旧 18080 会话/缓存与新克隆库不一致。
- 不打印、记录或提交 API Key、SMTP 密码、JWT secret、TOTP key、内部 token 或 dump 内容。

## 执行步骤

1. 建立 `deploy/backups/` 下的敏感本地备份文件：
   - `YYYYMMDD-HHMMSS-18084-candidate-for-18080-preview.dump`
   - `YYYYMMDD-HHMMSS-18080-preview-before-overwrite.dump`
2. 使用 `pg_dump -Fc` 从 `sub2api-candidate-postgres` 导出候选库到本地文件。该文件包含运行态敏感数据，不能提交。
3. 使用 `pg_dump -Fc` 备份当前 `sub2api-main-preview-postgres`。
4. 停止 `sub2api-main-preview` 应用容器，避免 restore 期间应用写库。
5. 在 `sub2api-main-preview-postgres` 内终止 preview DB 连接，drop/recreate `sub2api` 数据库。
6. 使用 `pg_restore --no-owner` 把 18084 dump 导入 preview DB。
7. 清空 `sub2api-main-preview-redis`。
8. 启动 `sub2api-main-preview`，让本地 main 镜像自动应用迁移。
9. 验证：
   - 18080 health。
   - 18084 health。
   - 18080 users/api_keys/schema_migrations 数量。
   - 18080 最新迁移应包含 `156_seed_codex_79_subscription_plan.sql`。
   - 18080 中公网账号存在。
   - 18080 `/api/v1/settings/public` 返回 200。
   - `sub2api-candidate` 启动时间和镜像不变。

## 回滚

如 18080 restore 或启动失败：

1. 停止 `sub2api-main-preview`。
2. drop/recreate preview DB。
3. 用 `YYYYMMDD-HHMMSS-18080-preview-before-overwrite.dump` 恢复原 preview DB。
4. 清空 preview Redis。
5. 启动 `sub2api-main-preview`。

回滚不涉及 18084，因为本流程不写入公网候选栈。
