# 七个模型渠道支付套餐配置方案

时间：2026-08-03 16:40:00（Asia/Tokyo）

## 现状

`/purchase` 的商品目录已按后端 `checkout-info.plans` 渲染订阅卡片，但 18082 的 `subscription_plans` 表为空，因此页面只有 API 余额卡。

当前七个可用模型渠道均为标准分组，不能直接改为订阅分组：这样会改变既有 API Key 分组选择权限。

## 方案

为每个现有渠道创建一个独立的订阅分组，复制原分组的路由设置以及账户、渠道关联；原标准分组保持不变。随后为每个新订阅分组创建一个 30 天、在售的订阅套餐。

流量包不创建、不迁移，也不加入 `/purchase`。

## 临时价格规则

当前没有可直接用于套餐的固定售价，因此按账户费率倍率确定临时价格：

- 月费（CNY）：账户费率倍率 `x 10`
- 周额度（USD）：账户费率倍率 `x 1`
- 有效期：30 天

得到的月费依次为：Grok 60、Claude Max 150、Claude Kiro 35、GLM 140、Kimi 350、DeepSeek 300、GPT 10（均为 CNY）。

## 风险控制

订阅分组不授予无限额度；每张卡配置周额度。所有新记录使用固定的 `duplicate_operation_id` / `product_name` 标识，便于审计和重复执行保护。
