# 订阅退款时间与额度双比例设计

## 结论

本文件取代 `20260729-182706-subscription-refund-ratio-reversal-design_CN.md` 和 `20260729-184143-subscription-refund-ratio-design-correction_CN.md` 的结论。前两份记录分别误解为反转额度比例及不需要代码改动；两者按协作规则保留，不修改、不删除。

订阅自动退款必须同时计算时间消耗和额度消耗：

```text
额度消耗比例 = clamp(已用额度 USD / 权益周期总额度 USD, 0, 1)
时间消耗比例 = clamp((报价时刻 - 权益开始时间) / (权益结束时间 - 权益开始时间), 0, 1)
实际消耗比例 = max(额度消耗比例, 时间消耗比例)
用户退款金额 = 订单本金 × (1 - 实际消耗比例)
```

因此，0% 时间且 0% 额度消耗时退订单本金全额；任一比例为 25% 时，29 元本金退款 21.75 元；任一比例达到 100% 时不可自动退款。

## 根因证据

订单 #60 的退款请求发生在原 30 天订阅接近到期时，但报价只使用 `$49.9390683 / $1032 = 4.839%` 的额度比例，忽略已过去约 29.9 天，导致报价 94.21 元。退款计算只依赖额度比例是根因。

## 服务端修改

- 退款报价从唯一可归属的 `payment_order` 权益段读取开始和结束时刻、周期总额度及已分配 usage facts。
- 计算并返回 `time_ratio` 与 `consumption_ratio`；保留 `usage_ratio` 表示额度消耗比例，保持现有字段兼容。
- `estimated_refund_amount` 改为以 `consumption_ratio` 计算。用户报价、管理员报价、余额退款、支付宝退款、管理员事务内重算仍共用该报价，禁止各入口自行计算。
- 权益段缺失、重叠、时间范围无效或历史用量无法唯一归属时，保持 `manual_review_required`，不猜测时间或额度。
- 退款本金继续使用 `payment_orders.amount`；手续费不退；订阅订单的网关退款金额继续等于退款本金。

## 前端展示

用户与管理员退款弹窗继续显示已用额度和额度使用比例，并新增时间消耗比例与实际消耗比例。预计退款直接使用服务端返回金额，前端不重算。

## 并发与边界

- 事务内重算沿用现有权益段和 usage facts 行锁；时间比例在同一事务内以执行时刻计算。
- 当前时刻早于权益开始时间按 0%，到达或超过权益结束时间按 100%。
- 非正权益时长直接进入人工审核，避免除零或错误全额退款。

## 验证

- 0% 时间、0% 额度：全额退款。
- 25% 时间、0% 额度：退款 75%。
- 0% 时间、25% 额度：退款 75%。
- 时间或额度达到 100%：不可自动退款。
- 时间比例高于额度比例时，用户、管理员、余额和支付宝退款均取时间比例；事务内新 usage fact 到达后仍按两者最大值重新报价。
- 前端类型与两个退款弹窗显示三个比例，且预计退款与服务端一致。
