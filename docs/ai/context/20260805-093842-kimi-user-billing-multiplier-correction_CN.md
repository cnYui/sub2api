# Kimi 用户计费倍率更正

## 背景与结论

用户提供的中转站截图表明，Kimi 中转站页面中的“用户扣费”已是该中转站面向其用户的价格层，不能再作为本平台用户余额扣费的倍率来源。本平台的业务口径为：

```text
本平台用户扣费 = 标准成本 × BILLING_FINAL_MULTIPLIER
                 = 标准成本 × 15
```

Kimi 不再叠加 `3.5x` 分组倍率。此前审计记录中将 Kimi `3.5x` 视为本平台应承担倍率的结论已被该截图和业务口径推翻；历史文件保留不改写。

## 已执行变更

- 生产 `groups.id=7` 的 `rate_multiplier` 已从 `3.5` 改为 `1.0`。
- 保持 `BILLING_FINAL_MULTIPLIER=15`，因此后续 Kimi token 请求按 `total_cost × 15` 扣费。
- 未改动 `accounts.id=5.rate_multiplier=35`；该字段用于账号统计/配额，不参与用户余额扣费。
- 未改动历史 `usage_logs`，也未直接修改用户余额。
- `groups` 更新触发 `trg_groups_auth_cache_invalidation`，为 Kimi 绑定 API Key 写入哈希化认证缓存失效事件；应用 worker 会删除 Redis L2 和进程 L1，并在 30 秒后执行第二次安全失效。
