# 购买确认与 ZPay 退款实现决策

## 目标

- `/purchase` 的套餐卡继续使用现有支付确认流程，支付成功后由回调完成订单和余额套餐到账。
- `/orders` 显示已支付订单，并允许用户对可退款的余额套餐订单发起自助退款。
- 退款调用创建订单时绑定的支付服务商实例（当前为 ZPay 易支付），不能切换到其他商户。

## 退款规则

余额套餐是 28 天周期权益。服务端按当前套餐记录的开始/结束时间和用户用量计算：

`时间比例 = clamp((当前时间 - 开始时间) / 周期时长, 0, 1)`

`额度比例 = clamp(周期内 usage_logs.actual_cost / 套餐承诺总额度, 0, 1)`

`消费比例 = max(时间比例, 额度比例)`

`预计退款 = max(购买本金 × (1 - 消费比例), 0)`

退款提交时会重新计算报价并锁定订单，前端报价只用于展示，不能作为最终退款金额。

## 套餐撤销边界

退款成功后将 `user_balance_packages.status` 标记为 `refunded` 并清空 `next_credit_at`，因此不会再发放后续周期余额。已进入用户余额的美元额度不跨订单追溯扣除，避免把用户原有余额误当成当前套餐余额；退款比例已将周期用量纳入计算。

## 状态与幂等

- 初次申请：`COMPLETED -> REFUNDING`，写入服务端复算的 `refund_amount`。
- ZPay 成功：订单状态为 `REFUNDED` 或 `PARTIALLY_REFUNDED`，套餐状态为 `refunded`。
- ZPay 失败：订单状态为 `REFUND_FAILED`，允许用户按原金额事实重试；不会重复撤销套餐。
- ZPay 待确认：保留 `REFUND_PENDING`，不执行套餐撤销，交由管理员查询确认。
