## 执行方式说明

前 3 次尝试通过管理后台 UI 逐个点击删除模型 chip 均失败，原因有二：

1. Browser pane 尺寸在会话中反复变化（innerWidth 在 366 / 1245 / 1391 之间跳动），
   截图坐标帧与 CSS 视口的换算比随之改变，坐标失准。
2. 即使坐标算对，模型 chip 的删除按钮（14×14 CSS px）被弹窗底部固定栏 `.modal-footer` 覆盖，
   `document.elementFromPoint` 命中的是 footer 而非按钮；误点还会落到遮罩上关闭弹窗、丢失改动。

因此改为调用管理后台自身的 `PUT /api/v1/admin/accounts/{id}` 接口完成（与前端保存走同一接口、同一鉴权）。
按 `EditAccountModal.vue:4163-4172` 的既有约定，请求体中**不携带 `api_key` 字段**时后端保留原加密凭证，
本次即依此只替换 `credentials.model_mapping`。

`credentials_status.has_api_key=true`、`base_url` 与分组绑定均未变，

- 已移除的 `gpt-5.2` 调用返回 `404 model_not_found`，白名单确实生效。
- 真实调用：上游B 三个分组（GPT0.16日常2/日常3/0.28）的 `gpt-5.4`、`gpt-5.6-terra` 均 `200`。
