# 2026-07-21 28 天周刷新与退款计费建议

## 推荐结论

建议把订阅从“30 天每日刷新”改为：

```text
28 天订阅周期 = 4 个 7 天额度窗口
```

- 不按自然月，不处理 28/29/30/31 天差异。
- 不存在 30 天最后 2 天额度不好算的问题。
- 用户提前续费时，新权益从当前权益 `expires_at` 后连续开始，不重叠、不吞额度。
- 用户断档后续费时，新权益从实际支付完成时间开始。


```text

28 天售价 = 原日额度 * 28 * 0.08 / 0.65
```

## 退款规则建议

如果做月总额度，不建议只按“已用额度 / 月总额度”退款，也不建议只按“已过时间 / 总时间”退款。

原因：

- 只按额度：用户 27 天不用，到最后一天几乎全额退款，平台承担了账号池预留和服务成本。
- 只按时间：用户第 1 天用完整月额度，再退 27 天费用，会亏。

推荐公式：

```text
时间消耗比例 = 已经过时间 / 28天
额度消耗比例 = 已使用额度USD / 28天总额度USD
实际消耗比例 = max(时间消耗比例, 额度消耗比例)
可退款 = 实付金额 * (1 - 实际消耗比例)
```

同时设置：

- 使用量达到或超过周期总额度：不可退款。
- 已发生网关手续费、通道手续费：不退或从可退款中扣除。
- 赠送额度、邀请返利、补偿金额不计入可退款本金。
- 退款后必须撤销剩余 entitlement period，并禁止继续使用该订阅。
- 共享订阅、人工赠送、离线付款、权益被管理员改动过的订单进入 `MANUAL_REVIEW`。

## 周刷新时的更简单退款口径

如果采用 4 个周窗口，可以用更强硬、更容易解释的规则：

```text
只退未开始的完整周窗口；
当前周只要有使用，就不退当前周；
已开始但未使用的当前周，可按 max(时间, 额度) 公式退。
```

示例：

- 买 59 元 28 天套餐，4 周，每周权益价值 `14.75 元`。
- 已用 1 周多，当前第 2 周已有使用：最多退第 3、4 周，即 `29.50 元`，再扣不可退手续费。
- 如果当前第 2 周完全未使用，可按实际经过时间或直接退剩余完整周，取决于产品规则。

## 最终建议

优先方案：

```text
28 天周期 + 每 7 天刷新 + 35% 毛利定价 + 退款按 max(时间消耗比例, 额度消耗比例)
```

更保守的执行规则：

```text
用户自助退款只退未开始的完整周；
复杂订单转人工审核。
```

这比月总额度更抗套利，也比每日刷新更容易解释。
