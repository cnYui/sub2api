# 余额恰为 0 时整笔透支：准入与扣费修复（2026-09-24）

## 起因

管理员问后台「余额」列里一批用户为什么严重欠费。只读排查（诊断密钥 SSH 进生产 Mac 查库）结论：

- 全站 35 个负余额用户合计 -$885.01，约 $793 来自 2026-09-17 的流量卡欠费舍入 bug 补扣，
  其中 user 529 一人 $744.95（见 `20260917-144451-traffic-debt-rounding-fix-backcharge_CN.md`）。
- user 506 的 -$34.26 是 08-07 负余额拦截上线前的旧欠费。
- **user 505（-$31.48）和 674（-$3.95）是本次修的问题**：两人扣费前余额都恰为 0，手上有流量卡，
  第一笔请求却整笔透支到了余额。
  - 505：09-23 22:52 买了 $30 流量卡；22:59 一次 gpt-6-astra 请求（14.8 万缓存写入 token，标准价 $1.85 × 17）$31.48 记到余额；之后的请求才走流量卡。
  - 674：09-17 新注册，余额 0，15:35/15:56 买了两张 $30 流量卡；15:58 第一笔 $3.95 记到余额，之后 1385 笔都走流量卡。

## 根因

两处都把 0 当成「有余额」：

1. **准入**：`BillingCacheService.checkBalanceEligibilityWithBalance` 和两个 API Key 中间件只拦 `balance < 0`，0 余额直接放行，不看流量卡。
2. **扣费**：`applyUsageBillingEffects` 在余额不足时，只有 `balanceBefore < 0` 才走流量卡，0 余额进入透支分支，整笔扣成负数。

后果：
- 有流量卡的用户第一笔被记成余额欠款。只买流量卡的用户不会再买余额套餐，这笔钱基本收不回（少收）。
- 什么都没买的新用户（`default_balance=0`）也能发一次任意大小的请求。生产当时有 155 个用户余额恰为 0。

## 修复

- 新增 `service.BalanceExhausted(balance, balanceBilled)`：欠费一律算耗尽；`balanceBilled=true` 时 0 余额也算耗尽。
- 准入（余额模式）、`APIKeyAuth`、`APIKeyAuthGoogle`：余额耗尽时必须有正数净额度的流量卡才放行，否则 403 `INSUFFICIENT_BALANCE`。
- 不扣普通余额的场景传 `balanceBilled=false`，0 余额照常放行、只拦欠费：
  - 简易模式（`[SIMPLE MODE] Usage recorded (not billed)`，余额恒为初始值，拦 0 会把所有简易模式用户挡在门外）；
  - 订阅分组（中间件按 `Group.IsSubscriptionType()` 判断；服务层订阅模式本来就不做余额检查）；
  - `CheckFreshBalanceDebt`（长连接首回合终检，不区分计费模式；0 余额规则已由握手时的 `CheckBillingEligibility` 执行）。
- 扣费事务：`balanceBefore <= 0` 时先尝试流量卡（允许部分扣），
  - 欠费，或 0 余额且流量卡扣到了钱 → 按流量卡结算，不足部分记 `traffic_credit_debt_ledger`，余额不动；
  - 0 余额且一张可用流量卡都没有 → 仍透支到余额。这只可能是并发把余额扣到 0（准入已拦住 0 余额无卡），
    这种用户多半是套餐用户，记在余额上才能被下一期套餐到账抵扣；记成流量卡欠费反而收不回来。
- **有意不改**：正余额但不够付这一笔（如余额 $0.50、请求 $30）仍整笔透支，这是 AGENTS.md 里「余额 > 0 不切流量卡」的既定口径。有流量卡时是否改成「先扣光余额、剩余走流量卡」，需要管理员另行决定。

## 测试

- 仓库层（sqlmock）：0 余额有卡足额 → 走流量卡、余额不变；0 余额卡不够 → 扣卡 + 记流量卡欠费；0 余额无卡 → 先查卡再透支；正余额不足 → 直接透支、不查卡。
- 服务层：`BalanceExhausted` 表驱动；余额模式 0 余额无卡拒绝、有卡放行；简易模式 0 余额放行；`CheckFreshBalanceDebt` 0 余额放行。
- 中间件：标准与 Google 两套，0 余额无卡 403、有卡放行且只查一次流量卡、简易模式放行；订阅分组 0 余额放行且不查流量卡；正余额不查流量卡。
- 旧测试里有 4 个把「0 余额放行 / 0 余额透支」钉死的断言，已按新口径改写。

## 上线后影响

- 生产 155 个 0 余额用户中，没有流量卡的会从「能用一次」变成直接 403「Insufficient account balance」（与负余额无卡同一提示）。
- 已经发生的 505、674 两笔欠款不在本次追溯范围内，仍是负余额，是否处理由管理员决定。
