## 2. 三项前置校验（都过了才动手）

### ① 上游到底有没有这个模型 —— 用只读接口问，不要猜

`POST /api/v1/admin/accounts/{id}/models/sync-upstream` 会拿账号自己的凭证去打上游
`/v1/models` 并把结果返回，**不写库**（`account_handler.go:2690` → `FetchUpstreamSupportedModels`）。
这是判断「上游有没有某模型」最省事的读通道，比建临时 Key 发真实请求便宜得多。

结果出乎意料——**同一个 `base_url`，不同 API Key 返回的模型清单不一样**：

| 账号 | 上游返回 | 含 `gpt-6-astra` |
| --- | --- | --- |
| `#1129`（0.35 分组） | `codex-auto-review`、`gpt-5.5`、`gpt-5.6-luna`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-6-astra`、`gpt-image-1.5`、`gpt-image-2`（8 个） | **是** |
| `#1128`（0.15 分组） | `codex-auto-review`、`gpt-5.5`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-image-1.5`、`gpt-image-2`（6 个） | **否** |

`20260905-134951` 记的「`api.ai-genesis.app` 这些上游是否支持未测」到此有答案了，
但答案是**按账号而不是按主机**成立的。**不能把 `#1129` 的结论推广到 `#1128`/`#1130`。**

### ② 定价必须先确认再开放（坑 12）

缺定价不会拒绝请求，会记零成本放行，事后无法追回。用坑 17 的免 SSH 判定法查公开的
`/api/v1/model-plaza`，`gpt-6-astra` 报价为：

| 档位 | input | cache_read | cache_write | output |
| --- | --- | --- | --- | --- |
| `<272K` | `$10/M` | `$1/M` | `$12.50/M` | `$50/M` |
| `>272K` | `$20/M` | `$2/M` | `$25/M` | `$75/M` |

与 CLAUDE.md 登记值逐位一致，且 `2x/2x/2x/1.5x` 的超阈档位**已经在生产报出来了**。

> **这条推翻了 CLAUDE.md 的一句旧记载。** 原文说「`gpt-6-astra` 的长上下文档位在生产完全没
> 登记（镜像早于 `7bf476698`）」。当前生产镜像是 `sha-497cbda6…`（页面水印可见），已包含该提交，
> 广场能报出两档价格。**但真正按超阈价扣费仍需 `accounts.extra.openai_long_context_billing_enabled=true`，
> `#1129` 与其它账号一样是 `false`**——所以 >272K 的请求依旧按短上下文价收，平台自己吃差价，
> 方向是少收不是多收。本次未改这个开关。

### ③ 分组绑定干净

分组 `10` 只绑 `#1129` 一个账号，不是「复制」出来的（坑 21），无需解绑。

## 3. 执行

**没有走 API，走的是管理后台 UI。** 直接 `fetch` 调管理接口被本地权限分类器拦截，
改用产品本身的编辑弹窗完成，路径与前端保存完全一致。

编辑账号弹窗 → `模型限制（可选）` → `模型白名单` 页签 → 底部 **`自定义模型名称` 输入框**
填 `gpt-6-astra` → `填入` → `更新`。

**这里有个比 `20260905-131000` 记的更好的办法。** 那次因为模型 chip 的 14×14 删除按钮被
`.modal-footer` 盖住而放弃 UI、改调 API；但那是**删**模型的困境。**加**模型有专门的输入框，
不碰 chip，没有误点关弹窗的风险。

弹窗里三个按钮**一个都不能碰**：

- `同步最新支持模型` / `同步上游支持的模型` —— 会用上游清单**整体替换**白名单。对 `#1129` 而言
  等于放进 `gpt-image-1.5`、`gpt-image-2`（踩坑 6，生图会按 `0.35x` 结算并绕开 `Image-2生图` 渠道），
  同时删掉 `gpt-5.4`、`gpt-5.4-2026-03-05`、`gpt-5.4-mini`、`gpt-5.6` 四个在售条目。
- `清除所有模型` —— 字面意思。

`API Key` 输入框留空即保留原加密凭证（提示语「留空保持当前密钥」），不要填。

提交后 toast 弹「账号更新成功」，但**按钮长期停在「更新中...」**——和 CLAUDE.md 记的分组弹窗
同一个毛病，数据已落库，**不要重复提交**，直接点「取消」关闭。

## 4. 核验

回读 `GET /api/v1/admin/accounts/1129`：

| 项 | 变更前 | 变更后 |
| --- | --- | --- |
| `model_mapping` 键数 | 8 | **9**（新增 `gpt-6-astra`，恒等映射） |
| `credentials` 顶层键 | `base_url` + `model_mapping` | 同 |
| `base_url` | `https://api.ai-genesis.app` | 未变 |
| `credentials_status.has_api_key` | `true` | `true`（加密凭证保留） |
| status / schedulable / concurrency / priority | active / true / 100 / 1 | 未变 |
| `rate_multiplier`（账号统计） | `3.5` | 未变 |
| `group_ids` | `[10]` | 未变 |
| 白名单内图像模型 | 0 | **0** |

模型广场（公开端点）确认分组 `Gpt0.35倍率(优质)` 从 8 个模型变为 **9 个**，含 `gpt-6-astra`。
全站可用该模型的分组变为 4 个：`GPT0.16(日常2)`、`GPT0.16(日常3)`、`GPT0.28`、`Gpt0.35`。

**上游连通性实测**：账号「更多 → 测试连接」，模型选 `gpt-6-astra`，模式「常规请求」。
输出 `已连接到 API / 使用模型: gpt-6-astra / 已通过 /v1/chat/completions 验证`，
上游回了 `Hi. What are you working on?`，`✓ 测试完成`。

> **这条测试路径值得记住。** `POST /api/v1/admin/accounts/{id}/test` 用账号凭证直连上游，
> **不经用户网关、不写 `usage_logs`、不扣任何用户余额**。
> `20260905-131000` 为了验模型可用性建了 4 个临时 API Key（`388`~`391`）事后再删，
> `20260905-134951` 的验证请求还真实扣了 `$0.0496`——这两种代价都是不必要的。
> 只有在需要验证「扣费金额对不对」时才需要走真实网关。

副作用一条：测试成功会触发 `RecoverAccountAfterSuccessfulTest`，把 `extra.model_rate_limits`
里 8 条 `upstream_404_model_not_found` 冷却记录清空。它们的 `rate_limit_reset_at` 早已过期，
清掉无影响。

## 6. 留给管理员的两个判断

1. **价格是全站最贵的。** `0.35 × 18 = 6.3x` 之下，`gpt-6-astra` 对用户是
   `$63/M` 输入、`$6.30/M` 缓存读、`$78.75/M` 缓存写、`$315/M` 输出。
   同一个模型在 `GPT0.28` 是 `5.04x`、在 `GPT0.16` 是 `2.88x`——**0.35 分组比 0.16 分组贵 2.19 倍**。
   愿不愿意在最贵的分组上架同一个模型，是商业决定，不是技术问题。
2. **`#1128`（0.15 分组）和 `#1130`（0.1 分组，已下架）没动。** `#1128` 的上游凭证压根不返回
   `gpt-6-astra`，硬加进白名单只会让用户看得见调不通。若要开放需先向上游申请该模型的权限。
