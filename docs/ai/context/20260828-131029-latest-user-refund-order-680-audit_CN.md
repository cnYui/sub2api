## 根因与风险

当前查询只按用户和套餐生命周期筛选：

```go
Where(
    usagelog.UserIDEQ(pkg.UserID),
    usagelog.CreatedAtGTE(pkg.StartsAt),
    usagelog.CreatedAtLT(pkg.ExpiresAt),
)
```

`usage_logs` 没有 `balance_package_id` 或扣费来源字段，无法区分余额套餐、普通余额、流量卡和流量卡欠费。`user_balance_packages.remaining_usd` 只保留当前窗口剩余值，刷新时会替换旧窗口，因此也不能仅靠历史余额状态可靠补算退款归属。

订单 `680` 的网关调用和套餐撤销流程是成功的，但该归因缺口会在余额套餐与流量卡/普通余额并存时造成少退款。后续若修复，应在扣费事务中持久化套餐来源（或建立不可变的套餐消费账本），退款按实际归属汇总；不能只继续扩大现有 `usage_logs` 时间范围查询。
