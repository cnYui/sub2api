## 5. 踩坑与可复用的事实

- 后台生成接口 `GenerateRedeemCodes` 出的码是 **32 位小写十六进制**（`GenerateRedeemCode`）。
  `RedeemService.GenerateRandomCode` 是另一种大写的 `XXXXXXXX-XXXXXXXX-…` 格式，两种生成器并存。
  兑换按原文精确匹配，邮件里的码必须和库里逐字一致。
- admin 写接口走 `executeAdminIdempotentJSON`（`RequireKey: true`），**不带 `Idempotency-Key` 会直接失败**，generate 和 send-email 都是这样。
- 响应外壳是 `{code, message, reason, metadata, data}`；生产 Mac 自带 `/usr/bin/jq`，可以在主机内直接解析。
- psql 的 `\echo` 文本里如果有单引号（比如 `today's`），会报 `unterminated quoted string`。失效的只是那一行 echo，后面的查询照常执行，看输出时别误判成 SQL 失败。
- 部署后要先断言镜像 tag，再用「码 ID 0 → 400」探测新路由，这比只看 CI 绿灯可靠。
- **`settings.value::json` 不能写在 WHERE 里**。settings 表里混着大量不是 JSON 的值，规划器可能先做转换、后按 key 过滤，于是报 `invalid input syntax for type json`。
  两种写法可以避开：用 `key LIKE 'redeem_code_delivery:%' AND value LIKE '%"user_id":712,%'` 这类纯文本条件过滤；或者先 LEFT JOIN 精确的 key，只在 SELECT 里做转换（第 4 节的回读 SQL 就是这样写的）。
