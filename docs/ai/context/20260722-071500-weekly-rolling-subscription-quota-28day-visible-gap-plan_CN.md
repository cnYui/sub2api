# 2026-07-22 周滚动订阅额度可见缺口补齐计划

## 背景

用户指出购买页等前端仍存在旧“30 天 / 日限额 / 24 点刷新”口径，说明此前实现只覆盖了核心周窗口和部分展示，没有完成设计文档要求的全链路可见契约。

## 本轮目标

- 后端公共 Codex 套餐 API 返回规范化 28 天、周额度、每 7 天刷新文案，避免旧数据库文案泄漏到购买页和结账页。
- Key 用量与订阅剩余额度对公共 Codex 周滚动订阅禁止回退到 group 完整周额度；没有权益窗口时按不可用处理。
- 更新套餐生成工具，未来公共 Codex 套餐默认生成 weekly/28 天口径。
- 前端购买确认页使用统一周额度文案兜底，不直接展示旧 description。
- 补充聚焦测试，覆盖旧文案输入下的 API 与页面输出。

## 不做事项

- 不执行公网、生产数据库、Nginx、Cloudflare、CLIProxyAPI 或 Docker 运行态操作。
- 不执行 cutover apply。
- 不提交、不推送。

## 验证

- 聚焦 Go 测试覆盖 payment handler 与 gateway remaining。
- 聚焦前端测试覆盖购买页旧文案不泄漏。
- 脚本执行 `bash -n`。
- 可行时继续跑全量后端与前端验证。
