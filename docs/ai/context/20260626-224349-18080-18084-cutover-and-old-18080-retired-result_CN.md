## 修复细节：候选容器 env 修正

切流到 18084 后候选容器之前用的是默认候选 env：`SECURITY_URL_ALLOWLIST_ALLOW_INSECURE_HTTP=false` / `SECURITY_URL_ALLOWLIST_ALLOW_PRIVATE_HOSTS=false`。候选 DB `accounts[1].credentials.base_url` 仍然是 `http://host.docker.internal:8317/v1`（与公网 18080 一致），导致候选后端走 `urlvalidator.ValidateURLFormat(raw, allowInsecureHTTP=false)` 时把 http 直接判为 `invalid url scheme: http`，落 `openai.forward_failed` 502。

修复动作：

1. 编辑 `/Users/wujianxiang/.trae/CodeSpace/sub2api/.worktrees/codex-sub2api-candidate-rehearsal-20260626/deploy/.env.candidate.local`：
   - `CANDIDATE_IMAGE=sub2api-candidate:20260626-220602-payment-template-30e66c82580f`
   - `CANDIDATE_SERVER_PORT=18084`
   - `SECURITY_URL_ALLOWLIST_ALLOW_INSECURE_HTTP=true`
   - `SECURITY_URL_ALLOWLIST_ALLOW_PRIVATE_HOSTS=true`
2. 仅 force-recreate 候选 app 容器，DB/Redis 不动：
   ```bash
   cd .worktrees/codex-sub2api-candidate-rehearsal-20260626/deploy
   PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH" \
     docker compose --env-file .env.candidate.local -f docker-compose.candidate.yml \
     up -d --no-deps --force-recreate sub2api-candidate
   ```
3. 候选健康后真实 API 验证通过（见上表）。
4. `docker stop sub2api` 把旧公网 app 容器退出，18080 端口空出。

## 易踩坑补充

- 候选 compose 走 `${CANDIDATE_IMAGE:?CANDIDATE_IMAGE is required}`，`.env.candidate.local` 里的 `CANDIDATE_IMAGE=sub2api-candidate:example` 是占位符；如果不先改这个 env 再 force-recreate，docker compose 会去 dockerhub 拉 `sub2api-candidate` 镜像并报 `pull access denied`。
- 候选 env 用的是 `.env.candidate.local`（不是公网 `.env.scheme-a.local`），两套 env 文件分开维护；未来如果继续以候选 worktree 作长期公网形态，建议把 `SECURITY_URL_ALLOWLIST_ALLOW_INSECURE_HTTP/ALLOW_PRIVATE_HOSTS` 写进 compose 默认值而不是依赖 env 文件覆盖。
- `weishaw/sub2api:latest` 当前 = `423e0593979c`（5 天前的旧镜像），未打 `sub2api-candidate:20260626-220602-...` 这个新镜像的 `latest` 标签。短期不影响（候选以具体 tag 启动），但回滚到 18080 之前必须先确认公网 env 文件与 latest 标签是否一致。
- 旧 `sub2api-postgres` / `sub2api-redis`（32 users / 22 api_keys / 188 migrations）尚未停；候选库已是新事实源，旧库如不再需要可在观察期后停掉并清理。
