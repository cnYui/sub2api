## 1. 结论

`gpt-5.6-sol` 与 `gpt-5.6`（后者被别名归一化改写为前者）按 **OpenAI 2026-08-24 降价前的旧价**计费：

| 维度 | 系统实际收 | 官方现价 | 偏差 |
| --- | --- | --- | --- |
| 输入 | $5 / M | **$4 / M** | **+25%** |
| 缓存读 | $0.50 / M | **$0.40 / M** | **+25%** |
| 缓存写 | $6.25 / M | **$5 / M** | **+25%** |
| 输出 | $30 / M | **$20 / M** | **+50%** |

因为 `actual_cost = total_cost × 分组倍率 × 18`，基础价偏差等比放大到用户账单。
**6 个在售 GPT 分组全部挂有这两个模型名**，影响面是全量。

对照组 `gpt-5.6-terra` 为 `2e-06 / 1.2e-05`，与官方一致——**不是系统性问题，
就是 sol 这一条没跟上降价**。

## 3. 根因：三层取价同错，重新同步目录修不好

| 层 | `gpt-5.6-sol` 的值 | 判定 |
| --- | --- | --- |
| ② 远端价格目录 | `5e-06 / 5e-07 / 6.25e-06 / 3e-05` | ❌ 旧价 |
| ③ 硬编码 `fallbackPrices["gpt-5.6-sol"]` | 与错值**完全相同**，注释还写着「官方价格」 | ❌ 旧价 |

**目录里存在正确的值**：裸 `gpt-5.6` 键是 `4e-06 / 4e-07 / 5e-06 / 2e-05`，与官方分毫不差。

但 `openai_model_alias.go` 的 `case normalized == "gpt-5.6": return "gpt-5.6-sol"`
在**查价之前**就把 `gpt-5.6` 改写成 `gpt-5.6-sol`，导致那条正确记录对计费**永远不可达**。
生产模型广场里 `gpt-5.6` 与 `gpt-5.6-sol` 数值完全相同，即为实证。

疑似成因：目录的 `gpt-5.6-sol` 与 `gpt-5.5` 除缓存写外完全相同（都是 `5 / 0.5 / 30`），
像是照抄 `gpt-5.5` 再补一个 1.25x 缓存写，降价后没更新。

**别名归一化本身没错**（官方定价页确实不单列 `gpt-5.6`），错的是 sol 的价。
修复应改价，不要动别名。

## 6. 同批审计的其它发现（同样未修复）

- **长上下文计费一道都没打开**。`accounts.extra.openai_long_context_billing_enabled`
  默认 false，且 OpenAI 网关是唯一默认关闭该计费的路径（Claude/Gemini/Grok 默认开着）。
  结果是 >272K 的 GPT 请求按短上下文单价收，**方向与 sol 相反，是平台自己吃差价**。
- **`gpt-6-astra` 的长上下文档位在生产完全没登记**，因为生产镜像早于 `7bf476698`。
  即使打开账号开关，astra 也会是唯一漏网的那个。
- **Codex 路径确实可能超过 272K**：网关对 Codex 原生路径无任何 token 级截断，
  且 remote compact 请求携带的是压缩前的完整上下文——**恰恰是最可能越过阈值的那一次**。
  所以长上下文档位不是理论问题。
- **`tier_label` 文案错误**：广场显示「输入 >=272K」，而实现是严格 `> 272000`，
  272,000 整走标准价。纯展示层，不影响计费。
- **远端目录的长上下文字段全部被丢弃**：目录用 `*_above_272k_tokens`，而
  `LiteLLMRawEntry` 只声明 `long_context_*` 三个 tag，Go 的 `encoding/json` 静默丢弃未知字段。
  目录里 `long_context_*` 命中数为 **0**。**同步远端目录不能自动维持长上下文计价正确。**
