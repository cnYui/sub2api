# Kimi 计费与模型广场价格修正

时间：2026-08-07

## 背景与口径

上游以人民币充值、美元余额 1:1 记账，但国产模型页面价格使用内部 `1 USD = 7 CNY` 换算。模型广场必须先以 Kimi 的美元基础单价计算，再应用 Kimi 用户侧的 `0.5x` 折扣；隐藏的 `BILLING_FINAL_MULTIPLIER=15` 只参与服务端实际扣费，不能显示在模型广场中。

因此，模型广场中显示的价格为：

`展示单价 = 校准基础单价 × 0.5`

实际请求扣费仍为：

`实际扣费 = 基础成本 × 分组/用户倍率 × BILLING_FINAL_MULTIPLIER`

本次生产 Kimi 分组（`groups.id=7`）倍率设为 `0.5`，没有用户专属倍率覆盖。

## 校准后的基础单价

单位均为 USD / 1M tokens。

| 模型 | 输入 | 输出 | 缓存读取 | 广场 0.5x 输入 | 广场 0.5x 输出 | 广场 0.5x 缓存读取 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Kimi K3 | $3.00 | $15.00 | $0.30 | $1.50 | $7.50 | $0.15 |
| Kimi K2.6 | $0.95 | $4.00 | $0.16 | $0.475 | $2.00 | $0.08 |
| Kimi K2.5 | $0.60 | $3.00 | $0.10 | $0.30 | $1.50 | $0.05 |

K3、K2.6、K2.5 固定复用本地校准 fallback 价，而不是远程 LiteLLM 目录价格。原因是远程目录的 Kimi 价格可能混入上游展示换算或发生同步漂移，若直接用于计费或广场会导致“官方价”和实付价不一致。

## 实现

- `BillingService` 对 K3、K2.6、K2.5 优先返回校准 fallback，统一实际计费和广场基准价。
- 模型广场补充读取账号绑定的模型映射；渠道配置缺失时，仍能显示可调度模型及其基础价。
- 广场官方参考价和可见计费价均复用同一计费解析结果，防止两条价格链路分叉。
- 新增单元测试覆盖动态目录价格与校准价冲突的场景，以及 Kimi 0.5x 页面展示。

## 验证

- Go 服务层测试通过。
- 前端模型价格表测试通过。
- 前端类型检查通过。
- 18082 容器健康检查、本地 Nginx 和公网模型广场接口均返回 HTTP 200。
- 本地与公网 Kimi 广场结果均为：K3 `$1.50 / $7.50 / $0.15`，K2.6 `$0.475 / $2.00 / $0.08`，K2.5 `$0.30 / $1.50 / $0.05`。
