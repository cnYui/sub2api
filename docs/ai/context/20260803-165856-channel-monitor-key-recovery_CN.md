# 渠道监控密钥恢复与 GPT 模型迁移

## 背景

渠道状态页面此前显示已配置渠道没有可用数据，GPT 监控还持续检测已下架的 `gpt-5.2`，导致可用性为 `0%`。

## 根因

容器重启时未持久化 `TOTP_ENCRYPTION_KEY`。服务启动后生成了新的随机密钥，历史保存的渠道监控 API Key 无法解密，检测任务因此失败。

同时，上游对 `gpt-5.2` 返回 `model_not_found`，该模型不再受当前账号组支持。

## 处理

- 为本地部署固定并持久化了加密密钥；密钥文件已忽略，不进入版本控制。
- 使用已有账号凭据重新保存了 7 条渠道监控的 API Key，令其以固定密钥重新加密。
- 将 GPT 渠道监控主模型从 `gpt-5.2` 更新为 `gpt-5.5`。
- 保持 7 条监控均为启用状态，检测周期保持 60 秒。

## 验证

- 管理端“立即检测”已返回 GPT `gpt-5.5` 正常，延迟约 2594ms，7 天可用率 100.00%。
- 公开 `/monitor` 已显示全部 7 个渠道，GPT 条目显示 `gpt-5.5`、正常、100.00%。
- 模型监控集合由手工配置的 `primary_model` 与 `extra_models` 决定；用户调用记录不会自动新增监控模型。
