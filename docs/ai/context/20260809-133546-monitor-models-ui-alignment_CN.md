# /monitor 模型目录探测展示对齐

## 背景

监控协议已统一为带鉴权的 `GET /v1/models`，每 30 分钟执行一次。该协议不再发送对话、Responses 或额外 PING 请求。

原用户侧监控卡片仍展示“对话延迟”和“端点 PING”。其中 `ping_latency_ms` 仅保留后端兼容字段，新的目录探测不会写入，导致页面持续显示空指标。

## 决策

- 卡片仅保留“模型目录延迟”，该值是最新 `/v1/models` 请求的端到端耗时。
- 指标组件支持单指标布局，以避免保留空白的第二张指标卡。
- 状态颜色逻辑保持不变：`operational` 为绿色，`degraded` 为黄色，`error` 与 `failed` 为红色。

## 原因

红色不是目录探测改造造成的前端误判。它表示本次 `/v1/models` 返回了真实错误，例如上游 `401 INVALID_API_KEY`。将这些结果改成绿色会把上游凭证故障错误地呈现为可用。

## 范围

本次只调整用户侧 `/monitor` 指标文案和布局，不修改后端探测协议、历史状态、可用率计算或状态颜色语义。
